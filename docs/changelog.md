# Улучшения и безопасность (2026-09-07)

### Окружение и секреты
- Секреты вынесены из кода/композа в корневой **`.env`** (в `.gitignore`); образец — `.env.example`. `docker compose` требует `POSTGRES_PASSWORD` и `JWT_SECRET_KEY`, при отсутствии файла `.env` останавливается с понятной ошибкой.
- `backend/core/config.py`: `JWT_SECRET_KEY` читается из окружения; если не задан — в лог пишется предупреждение (используется только dev-запасной ключ).
- **Требует действий:** смените `JWT_SECRET_KEY`/пароль БД, если значения попадали в публичный git (ротация + пересоздание volume). Старый файл `.env.dev` удалён из индекса.

### Аутентификация (OTP)
- OTP-коды теперь хранятся в **БД** (`otp_codes`, хеш + счётчик попыток), а не в памяти — переживают рестарт и работают при нескольких воркерах.
- Защита от перебора: лимит неверных попыток (`AUTH_OTP_MAX_ATTEMPTS`, по умолч. 5), кулдаун повторной отправки (`AUTH_OTP_RESEND_COOLDOWN_SECONDS`, 30 с, HTTP 429 + `Retry-After`).
- Удалены отладочные эндпоинты `/auth/basic-auth*`.
- Доп. защита (2026-09-08): часовой лимит запросов кода на номер (`AUTH_OTP_REQUEST_PER_PHONE_PER_HOUR`, 10) и блокировка номера после перебора (`AUTH_OTP_VERIFY_LOCKOUT_SECONDS`, 120 с, HTTP 429).

### Загрузка файлов
- Вложения и аватары проверяются: расширение из белого списка + сигнатура (magic bytes) для изображений. HTML/SVG/JS/XML и неизвестные типы отклоняются (защита от stored-XSS через `/media/...`).
- Импорт GIF: запрещены HTTP-редиректы (защита от SSRF), проверяется host, порт/userinfo и что ответ действительно GIF.
- **Квота на медиа** (`core/media_quota.py`, `MEDIA_QUOTA_BYTES`, по умолчанию 500 МБ):
  ограничивает накопление файлов у одного пользователя — размер одного файла был
  ограничен и раньше (15 МБ), а суммарный объём нет. Считаются только файлы,
  загруженные самим пользователем: пересылка переиспользует тот же файл на диске
  (`file_url` копируется), поэтому второй раз в квоту он не попадает. Аватар (один
  файл до 8 МБ) в квоту не входит.
- Превышение → `413` с цифрами («Хранилище заполнено: занято 250.0 МБ из 500.0 МБ»),
  проверка идёт **до** записи файла на диск (и в воркере для GIF). Место
  освобождается сразу после удаления сообщения, потому что квота считается по БД;
  осиротевшие файлы убирает ночная задача `cleanup_orphan_media`.
- `GET /api/v1/users/me/storage/` → `{used_bytes, quota_bytes, files, percent}` —
  профиль показывает индикатор заполненности (и предупреждает заранее при ≥90%).
  Квота `0` выключает ограничение (аварийный режим).

### Присутствие и БД
- `last_seen` больше не обновляется в `get_current_user` (не было лишних commit на каждый read-only запрос); теперь присутствие обновляется в poll-эндпоинте `GET /chats/`.
- При удалении сообщения его файл удаляется с диска (best-effort).
- `GET /messages/{chat_id}/media/` — вложения чата для галереи «Медиа/Файлы»:
  `kind=image|video|audio|file` и `before_id` листают вложения без выгрузки
  истории (по умолчанию **60**). В зашифрованном чате возвращается пустой
  список: содержимое зашифровано ключом чата, галерея строится из расшифрованной
  ленты (сервер не может показать картинку и определить тип).
- `GET /messages/{chat_id}/` всегда отдаёт страницу: по умолчанию последние **100** (`DEFAULT_MESSAGE_PAGE_SIZE`); `?limit=`/`?before_id=` — пагинация «вверх». Добавлен индекс `(chat_id, timestamp)`.

### Итерация 2 (2026-09-07)

- **Логирование**: SMS-заглушка пишет через `logging` вместо `print`.
- **Зависимости**: `python-jose` удалён; `PyJWT` добавлен явно (именно его использует `import jwt`). Обновился `poetry.lock` (убраны rsa/pyasn1/six).

### Итерация (2026-09-12): аватары-миниатюры, галерея медиа, скорость голосовых, бейдж

- **Аватары**: сервер рядом с оригиналом кладёт миниатюру 128px
  (`core/avatar_store.py`, Pillow) и отдаёт `avatar_thumb_url`; клиент перед
  загрузкой сжимает фото до 512px (`optimizeAvatarFile`); интерфейс берёт
  миниатюру (`avatarUrlOf`/`groupAvatarUrl`), оригинал — только для крупного
  показа (`avatarFullUrlOf`). На кружок в списке чатов уходит миниатюра
  вместо оригинала: на реальных аватарах прод-сервера 58–60 КБ → 2–5 КБ, на
  лабораторном снимке 3000×2000 — 1.2 МБ → 1–2 КБ (замеры — в
  `docs/feed-performance.md`). Для уже загруженных
  аватаров миниатюры досоздаёт `python -m scripts.make_avatar_thumbs --apply`.
- **Галерея медиа**: `GET /messages/{chat_id}/media/` отдаёт вложения всей истории
  чата (фильтр `kind=image|video|audio|file`, пагинация `before_id`), а не только
  загруженные ~100 сообщений; в «Информации о чате» появилась кнопка «Показать
  ещё», а картинка вне загруженной ленты подгружает свою страницу и открывается в
  лайтбоксе. В зашифрованном чате список пуст (галерея — из расшифрованной ленты).
- **Скорость голосовых и видеосообщений**: кнопка `1×/1.5×/2×`
  (`utils/playbackSpeed.ts`), выбор общий для всех сообщений.
- **Бейдж приложения**: число непрочитанных ставится на иконку установленного PWA
  (`utils/appBadge.ts`); при push в закрытое приложение service worker ставит
  «точку».
- **«Ответить» из уведомления**: кнопка в системном уведомлении открывает чат
  с уже сфокусированным полем ввода (печатать текст прямо в уведомлении веб-
  приложению нельзя — такого API нет, поэтому «быстрый ответ» это чат, готовый
  к вводу; `?reply=1`, `isReplyLaunch`).
- **Мелочи**: убраны мёртвый CSS `.gif-btn` (вес 800 в шрифте, которого нет) и
  неиспользуемые импорты; предзагрузка иконочных шрифтов в `index.html`; скрипты
  очистки медиа (`cleanup_orphan_media`, `tasks/media_tasks`) больше не считают
  «сиротами» миниатюры аватаров и аватары групп (раньше удалили бы их как
  неиспользуемые).

### Итерация (2026-09-12, вторая): ссылки-приглашения в группы и починка звонка из push

- **Ссылки-приглашения в группы**: создатель или админ делает ссылку в карточке
  группы (`/chats/{id}/invites/`), отправляет её другу; тот открывает
  `https://<домен>/j/<токен>`, видит карточку группы (название, аватар, число
  участников) и вступает. Ссылку можно ограничить по сроку (`expires_in_hours`) и
  числу входов (`max_uses`) и отозвать. Повторный вход тем же человеком ничего не
  ломает и лимит не тратит; создатель, вернувшийся по ссылке, снова получает роль
  создателя. В зашифрованную группу вход по ссылке закрыт: ключ группы выдаёт
  участник, а не сервер (409 с понятным текстом).
- **Звонок из push**: кнопка «Ответить» больше не выглядит как отказ.
  * неудачная попытка принять (`reason: failed`) и «занят» (`busy`) больше не
    записываются в историю как «отклонён» — это пропущенный звонок;
  * отказ по кнопке уведомления теперь попадает в историю (раньше проходил мимо
    неё: зовущий видел «отклонил», а записи о звонке не было);
  * на экране ожидания звонка (приложение открыто кнопкой «Ответить», offer ещё в
    пути) есть обе кнопки — «Ответить» и «Отклонить», а не одна красная;
  * действие из уведомления не теряется, если offer уже пришёл.
- **Мелочи**: если чат удалили или вас исключили из группы, а он был открыт,
  приложение убирает его из списка и возвращает к чатам (раньше фоновое обновление
  бесконечно писало «Не удалось обновить сообщения»); карточка приглашения грузится
  отдельным чанком, поэтому основной бандл остался в бюджете размера.

### Итерация (2026-09-15): файлы перетаскиванием в любое место окна и вставкой из буфера

- **Перетаскивание**: файл можно бросить в любое место окна — на ленту
  сообщений, список чатов, шапку. Слушатели живут на `window`
  (`composables/useFileDrop.ts`), подсказка одна на всё приложение
  (`components/messenger/FileDropOverlay.vue`): затемнение + карточка с пунктиром
  «Отпустите файл, чтобы отправить» и пометкой «Можно перетащить несколько файлов
  сразу». Без открытого чата подсказка меняется на «Откройте чат, чтобы отправить
  файл», и сам бросок показывает уведомление.
- **ПОЧЕМУ окно, а не зона у композера** (первый заход, до коммита, был именно
  таким): `dragover`/`drop` в браузере — это навигация, поэтому бросок мимо зоны
  **открывал файл вместо чата**, то есть терял приложение вместе с неотправленным
  сообщением. Гасить события надо на всём окне, а раз цель одна — и подсветка
  одна: два индикатора (у полосы ввода и оверлеем) спорили между собой, а
  оставшийся в композере обработчик продублировал бы отправку.
- **Несколько файлов за раз**: уходят по очереди, каждый — отдельным сообщением
  (альбомов в модели сообщений нет). Подпись из поля ввода достаётся первому —
  после него поле очищается, как при отправке одного файла. Один неудачный файл не
  отменяет остальные: композер показывает «Не удалось отправить N из M файлов»,
  одиночный — свою причину.
- Отправка идёт тем же путём, что и кнопка «Прикрепить», поэтому сжатие фото,
  квота и E2EE-конверт работают без отдельной ветки кода.
- **Вставка картинки из буфера**: Ctrl+V с картинкой в поле ввода отправляет её
  вложением; обычный текст по-прежнему вставляется как текст.
- Тесты: `useFileDrop.spec.ts` (9 — включая «гасит поведение браузера»),
  `fileDropOverlay.spec.ts` (4), `composerPaste.spec.ts` (3). Проверено в браузере
  (headless Chrome + CDP): бросок двух файлов над лентой отправил два сообщения,
  события погашены, обе подсказки на месте (тестовые сообщения удалены).
- Бюджет размера бандла обновлён (`frontend/scripts/bundle-size-baseline.json`):
  от HEAD основной чанк вырос на 934 Б gzip (весь новый код перетаскивания) плюс
  475 Б CSS, а сама база к тому же отставала от HEAD на 2,7 % — без обновления
  проверка падала бы.

### Итерация (2026-09-15): видеосообщение получило свою иконку — «кружок в квадрате»

- **Было**: и видеозвонок, и видеосообщение («кружок») рисовались одним глифом —

  (`src/utils/icons.ts`). Сборка шрифта (`scripts/build_icons.py`) их пропускает —
  без этого падала бы на «нет в Lucide».
- Сетка и штрих нового глифа как у Lucide (поле 24, фигура 18, штрих 2): рядом с
  соседними иконками он не выглядит ни жирнее, ни крупнее.
- Шрифт иконок не пересобирали: рисованный глиф в него не попадает, а пересборка
  тянет свежую версию Lucide — поехали бы глифы всех остальных иконок. В
  `icons.css` обновилась только шапка (там было старое имя скрипта сборки и не
  было сказано про рисованные глифы).
- Глиф стоит в композере (переключатель режима записи), в заголовке
  полноэкранного просмотра кружка и в `fileIcon()` для `video/*`; камкордер
  `videocam` оставлен только за звонками (`ChatHeader.vue`, `CallOverlay.vue`,
  `callMessageIcon()`).
- Тесты: `icons.spec.ts` (разные глифы у `videocam` и `video_message` + форма
  глифа разбирается из маски), `media.spec.ts` (иконка видео ≠ иконка видеозвонка).

### Итерация (2026-09-15): кнопка записи в композере стала акцентной

- **Было**: кнопка записи (микрофон / кружок-видео) была серой, как служебные
  «прикрепить» и «эмодзи» рядом.

- ГРАБЛЯ: цвет при наведении задаёт общий слой (`html .messenger-shell .round-btn:hover`
  в `appearance.css`) и он же красит иконку в `--ms-text`. У слоя специфичность
  выше scoped-правила (0,3,1 против 0,3,0), поэтому акцент возвращается только
  через `:global(html .messenger-shell .mic-hold-btn:hover)` — тот же приём, что в
  `StoriesStrip.vue` для фокуса.
- Заодно порядок состояний: `.mic-hold-btn.holding` объявлен ПОСЛЕ `.mode-video`,
  поэтому во время записи кружка кнопка заливается акцентом (раньше в режиме видео
  оставалась бледная подложка, хотя запись уже шла).

### Итерация (2026-09-15): согласие при регистрации, админская «шестерёнка», приглашения из приложения

**Согласие с документами сервиса (регистрация).**
- Раньше под кнопкой была только строка «Продолжая, вы соглашаетесь…» — явного
  действия не требовалось. Теперь при регистрации нужна **галка**
  (`components/common/ConsentCheckbox.vue`): она обязательна на шаге подтверждения
  кода для НОВОГО номера (там сервер и создаёт аккаунт, `/auth/verify-otp/`) и на
  шаге создания пароля для нового номера, а также на регистрации по приглашению.
  При обычном входе и при «задать пароль» существующему аккаунту галки нет —
