# Публикация Pismo в RuStore

Практическая инструкция: что уже готово в репозитории, что нужно сделать один
раз и как пройти модерацию. Требования сверены с документацией RuStore
(`rustore.ru/help`) на 10 сентября 2026 г. — при расхождении ориентируйтесь на
консоль, она меняется чаще документации.

## 1. Что уже готово

| Готово | Где |
|---|---|
| Android-приложение (WebView-оболочка + RuStore Push SDK) | `android/` |
| Сборка AAB/APK без установки SDK на хост (Docker) | `android/Dockerfile.build`, `scripts/rustore/build_android.sh` |
| Иконки приложения: launcher, adaptive, круглая, уведомления, сплэш | `scripts/gen_android_icons.py` → `android/app/src/main/res/**` |
| Push-уведомления RuStore (клиент + отправка с сервера) | `android/.../PismoMessagingService.java`, `backend/core/rustore_push.py`, `backend/tasks/notifications.py` |
| Регистрация push-токена на сервере | `POST /api/v1/push/rustore/subscribe/` |
| App Links (ссылки `pismo.space` открываются в приложении) | `frontend/public/.well-known/assetlinks.json` + `scripts/rustore/write_assetlinks.sh` |
| Политика конфиденциальности | `frontend/public/privacy.html`, `docs/privacy-policy.md` |
| Жалоба на контент, блокировка пользователя, удаление аккаунта (UGC) | `backend/api_v1/moderation/`, `backend/api_v1/users/deletion.py`, `frontend/src/components/messenger/{ReportDialog,BlockedUsersDialog,DeleteAccountDialog}.vue` |
| Разбор жалоб модератором | `GET/PATCH /api/v1/moderation/reports/` (только `is_superuser`), экран «Жалобы» в меню «⋯» |
| Скрипт скриншотов для карточки | `scripts/rustore/screenshots.mjs` |
| Ключ подписи (генерация) | `scripts/rustore/new_keystore.sh` |

Веб-версия и PWA при этом не меняются: Android-приложение открывает тот же самый
веб-клиент с `https://pismo.space`, а push идут в два канала — Web Push для
браузера и RuStore Push для приложения.

## 2. Предварительные условия

1. **Аккаунт разработчика в RuStore Консоль** (`console.rustore.ru`) — физлицо,
   ИП или ООО. Публиковать приложение может только «Владелец компании».
2. **Статус оператора персональных данных** (152-ФЗ): мессенджер обрабатывает
   номера телефонов и переписку. RuStore требует, чтобы оператор был
   зарегистрирован (уведомление в Роскомнадзор), а пользователь был уведомлён о
   сборе данных. Реквизиты оператора нужно вписать в
   `frontend/public/privacy.html` и `docs/privacy-policy.md` (сейчас там
   заглушки «ЗАПОЛНИТЕ»).
3. **Домен с TLS**: `https://pismo.space` (Let's Encrypt уже настроен в
   `frontend/nginx.prod.conf`). Проверьте, что доступны
   `https://pismo.space/privacy.html` и
   `https://pismo.space/.well-known/assetlinks.json`.
4. **Проект push в RuStore**: RuStore Консоль → **Push-уведомления → Проекты**.
   Запишите **ID проекта** и **сервисный токен**.
5. **Ключ подписи**: сгенерировать и сохранить (см. §4). Один ключ на все версии.

## 3. Уведомления: RuStore Push

Android-оболочка использует собственный push-сервис RuStore (работает без
Google-сервисов), PWA — обычный Web Push. Настраивается один раз:

1. В консоли RuStore создайте проект push-уведомлений и скопируйте ID проекта.
2. Сервер: добавьте в корневой `.env`

   ```dotenv
   RUSTORE_PUSH_PROJECT_ID=<ID проекта>
   RUSTORE_PUSH_SERVICE_TOKEN=<сервисный токен>
   ```

   и перезапустите `web`/`worker` (`docker compose -f docker-compose.test.yaml up -d web worker`).
   Эти же переменные уже проброшены в compose-файлах.
3. Приложение собирайте с ID проекта:

   ```bash
   ./scripts/rustore/build_android.sh bundleRelease -PrustoreProjectId=<ID проекта>
   ```

4. Проверка: токен устройства появится в БД —
   `SELECT count(*) FROM rustore_push_tokens;` (в dev это будет 0, пока не
   установлено приложение из RuStore).

**Условия доставки** (все обязательны, иначе push не придут):

- на устройстве установлен RuStore актуальной версии;
- пользователь авторизован в RuStore;
- RuStore разрешена установка приложений и работа в фоновом режиме;
- приложение не заблокировано, используется актуальная версия SDK.

Если условия не выполнены, `RuStorePushClient.getToken()` возвращает ошибку
(`UnauthorizedException`, `HostAppNotInstalledException`,
`HostAppBackgroundWorkPermissionNotGranted`) — веб-клиент в этом случае просто
не регистрирует токен, приложение продолжает работать (уведомлений нет).

## 4. Ключ подписи и сборка

```bash
# 1. Ключ (пароли вводятся вручную, нигде не сохраняются кроме keystore.properties)
./scripts/rustore/new_keystore.sh
# заполните android/keystore.properties по образцу keystore.properties.example

# 2. Проверка сборки (debug APK)
./scripts/rustore/build_android.sh assembleDebug

# 3. Артефакт для RuStore
./scripts/rustore/build_android.sh bundleRelease -PrustoreProjectId=<ID>
# → android/app/build/outputs/bundle/release/app-release.aab

# 4. App Links: прописать отпечаток ключа в assetlinks.json
./scripts/rustore/write_assetlinks.sh
# затем пересобрать и задеплоить фронтенд
```

При загрузке **AAB** RuStore попросит загрузить подпись отдельно (`.jks` +
alias/пароли) — можно указать файл `android/keystore/pismo-release.jks`; при
загрузке **APK** подпись уже внутри файла. RuStore рекомендует хранить ключ
локально и использовать один и тот же сертификат во всех магазинах, иначе
пользователи не смогут обновлять приложение.

## 5. Публикация в консоли (чеклист)

**Файл и версия**

- [ ] Загрузить `app-release.aab` (лимит 5 ГБ), дождаться обработки.
- [ ] Заполнить «Что нового?».
- [ ] `versionCode` увеличивать при каждой новой версии (в `gradle.properties`
      или `-PpismoVersionCode=…`), `versionName` — по смыслу (1.0.1, 1.1.0).
- [ ] Декларировать разрешения и категории данных (§6).

**Информация о приложении**

- [ ] Название: `Pismo` (≤ 30 символов, должно быть уникальным).
- [ ] Категория: «Общение» (или ближайшая подходящая).
- [ ] Возрастное ограничение: для мессенджера без модерации контента RuStore
      обычно требует 18+ либо 12+ с премодерацией — выбирайте по факту
      (см. §7 про UGC).
- [ ] До 5 поисковых тегов: `мессенджер`, `чат`, `звонки`, `Pismo`.
- [ ] Краткое описание (≤ 80 символов), например:
      `Мессенджер Pismo: чаты, звонки, файлы и медиа.`
- [ ] Подробное описание (≤ 4000 символов) — что умеет приложение, чем
      отличается (E2EE-чаты, звонки, обмен медиа, тёмная тема).
- [ ] Контакты разработчика — минимум одно из: e-mail, группа ВК, сайт, MAX.
      Укажите `admin@pismo.space`.
- [ ] **Комментарии для модераторов**: обязательно дайте тестовый аккаунт
      (номер + пароль) и опишите сценарии проверки (вход, чат, звонок). Без
      этого модерация не сможет проверить вход по номеру.

**Медиа**

- [ ] Иконка: 512×512, PNG/JPG, ≤ 3 МБ, фон заполняет всю площадь (без
      прозрачных краёв). Готовый файл: `frontend/public/icons/icon-512.png`.
- [x] Скриншоты телефона: **минимум 3**, PNG/JPG, ≤ 3 МБ, 16:9, до 2160×3840.
      Готовые кадры (1080×1920, 5 шт.) — `docs/rustore-assets/screenshots/`
      (`01-login`, `02-chats`, `03-chat`, `04-profile`, `05-appearance`).
      Переснять: `scripts/rustore/screenshots.mjs` (см. комментарий в файле:
      нужен Playwright; на хосте с обычным Chrome — `PISMO_BROWSER_CHANNEL=chrome`).
- [ ] По желанию: скриншоты планшета, видео VK.

**Правовое**

- [ ] Политика конфиденциальности: `https://pismo.space/privacy.html`.
- [ ] Подтвердить, что у вас есть статус оператора ПДн и согласие пользователей
      (в приложении на экране входа есть ссылка на политику и текст о согласии).

## 6. Декларация разрешений и данных

В консоли при загрузке версии нужно заполнить раздел «Безопасность данных»:
категории и типы данных + чувствительные разрешения. Наше приложение
запрашивает:

| Разрешение | Зачем | Категория RuStore |
|---|---|---|
| `INTERNET`, `ACCESS_NETWORK_STATE` | работа мессенджера | разрешённые |
| `CAMERA` | видеозвонки, видео-кружки, отправка фото | **чувствительное** |
| `RECORD_AUDIO` | голосовые сообщения, аудиозвонки | **чувствительное** |
| `MODIFY_AUDIO_SETTINGS` | управление звуком звонка | разрешённое |
| `POST_NOTIFICATIONS` | уведомления (Android 13+) | разрешённое |
| `VIBRATE`, `WAKE_LOCK` | уведомления и звонки | разрешённое |

Типы данных, которые нужно задекларировать: номер телефона, имя/фамилия,
e-mail (если указан), сообщения, фото/видео/аудио, файлы, идентификаторы
устройства и push-токены. Разрешения из категории «Запрещённые»
(`Not for use by third-party applications`) приложение не использует —
проверить можно так:

```bash
grep -o 'uses-permission[^/]*android:name="[^"]*"' android/app/src/main/AndroidManifest.xml
```

## 7. Требования модерации: на что смотрят

1. **Самодостаточность (важно для WebView-оболочки).** RuStore прямо не
   приветствует приложения, единственная цель которых — перенаправление на сайт.
   У нас оболочка ведёт себя как полноценное приложение: нативный сплэш, иконки,
   разрешения, push через RuStore, экран «Нет соединения», обработка кнопки
   «назад», App Links. В описании и комментариях для модераторов подчеркните,
   что это мессенджер, а не витрина сайта.
2. **Пользовательский контент (UGC).** Для мессенджера RuStore требует:
   определение неприемлемого контента, **механизм жалобы на оскорбительный
   контент**, **блокировку пользователей**, контакты поддержки.
   Всё это реализовано:
   - «Пожаловаться» — в меню «⋯» шапки личного чата и в меню каждого чужого
     сообщения (`POST /api/v1/moderation/reports/`, причины: спам, оскорбления,
     мошенничество, угрозы, другое + комментарий);
   - «Заблокировать» — там же (и в списке «Заблокированные» в «⋯» списка чатов);
   - «Удалить аккаунт» — в профиле (`DELETE /api/v1/users/me/`, с паролем и
     подтверждающим словом).
   Разбор жалоб — служебный экран «Жалобы» в «⋯» у администратора
   (см. §9.1). Контакты поддержки — `admin@pismo.space`.
3. **Работоспособность.** Приложение должно запускаться и работать без сбоев;
   тестовый доступ для модераторов обязателен. Проверьте на «холодном» старте
   без сети — покажется экран «Нет соединения» с кнопкой «Повторить».
4. **Персональные данные.** Нужен статус оператора ПДн, уведомление и согласие
   пользователя (§2, §5).
5. **Язык.** Интерфейс на русском — требование выполняется.
6. **Версии.** RuStore может снять приложение, если в другом магазине версия
   выше; держите версии синхронно.
7. **Обновления.** Пользователю должно предлагаться обновление именно через
   RuStore (штатная проверка обновлений RuStore делает это сама).

## 8. Обновление версии

```bash
# 1. изменить код/веб-часть, задеплоить pismo.space
# 2. поднять versionCode (и versionName)
./scripts/rustore/build_android.sh bundleRelease -PrustoreProjectId=<ID> \
    -PpismoVersionCode=2 -PpismoVersionName=1.1.0
# 3. загрузить AAB в существующую карточку → «Новая версия», заполнить «Что нового»
```

Веб-часть обновляется без выпуска в RuStore: приложение открывает живой сайт,
поэтому изменения в интерфейсе и функциональности появляются сразу после
деплоя `frontend`. Новый AAB нужен только при изменении нативной части
(иконки, разрешения, push, целевые SDK, поведение WebView).

## 9. Что стоит доделать перед публикацией

- [x] **Жалоба и блокировка пользователя** (требование для UGC): «Пожаловаться»
      в шапке/меню чата и в меню сообщения, «Заблокировать пользователя»
      (диалог скрывается, сообщения в обе стороны не доставляются, снять можно
      в «⋯» → «Заблокированные»).
- [x] **Удаление аккаунта из приложения** — профиль → «Удалить аккаунт»
      (пароль + слово-подтверждение); удаляются медиа, сообщения, чаты, ключи
      E2EE, push-подписки и сам аккаунт.
- [ ] Заполнить реквизиты оператора ПДн в политике.
- [ ] Проверить на живом устройстве: вход, звонок, запись голосового, отправка
      файла, push о сообщении и о входящем звонке, клик по уведомлению.
- [ ] Проверить, что `https://pismo.space/privacy.html` и
      `/.well-known/assetlinks.json` отдаются продакшен-nginx.

## 9.1 Разбор жалоб (для модератора)

Жалобы попадают в таблицу `user_reports` со статусом `new`. Экран «Жалобы»
появляется в меню «⋯» списка чатов **только у администратора**. Чтобы назначить
администратора, пометьте пользователя в БД:

```bash
# на сервере (в каталоге проекта)
docker compose exec -T db psql -U postgres -d microshop \
  -c "UPDATE \"user\" SET is_superuser = true WHERE phone_number = '+79001234567';"
```

После повторного входа (или перезагрузки страницы) в «⋯» появится пункт
«Жалобы»: фильтры «Новые / В работе / Решённые / Отклонённые / Все», карточка
показывает, кто на кого пожаловался (имя и телефон), причину, комментарий,
текст сообщения и контекст (чат/сообщение), есть поле заметки. Кнопками
«В работу / Решена / Отклонить» статус меняется, уходит время разбора
(`reviewed_at`). Те же данные доступны по API (только администратору):

```bash
# список (только новые)
curl -H "Authorization: Bearer $TOKEN" \
  'https://pismo.space/api/v1/moderation/reports/?status=new'
# статус + заметка
curl -X PATCH -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"status":"resolved","note":"пользователь предупреждён"}' \
  https://pismo.space/api/v1/moderation/reports/12/
```

Обычные пользователи (и гости) получают от этих эндпоинтов 403/401 — жалобы
чужим не видны.
