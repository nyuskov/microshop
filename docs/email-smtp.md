# Включение e-mail-канала (подтверждение адреса, вход по коду, сброс пароля)

Канал писем **выключен, пока не заданы SMTP-настройки**: тогда в профиле стоит
«Не подтверждён (отправка писем на сервере выключена)», а на экране входа нет
кнопок «Войти по коду на e-mail» и «Забыли пароль?». Код входа по-прежнему приходит
в Telegram — это не ошибка, а выключенный второй канал.

Проверить состояние канала:

```bash
curl -s https://pismo.space/api/v1/auth/channels/
# {"otp_available":true,"email_otp_available":false}   ← письма выключены
```

## Быстрый путь: пароль приложения у почтового провайдера

Нужен **пароль приложения** (не обычный пароль от почты). Для Gmail он появляется
только при включённой двухэтапной аутентификации:

| Провайдер | Хост | Порт | Где взять пароль |
|---|---|---|---|
| Gmail | `smtp.gmail.com` | 587 (STARTTLS) | Аккаунт Google → Безопасность → Двухэтапная аутентификация → **Пароли приложений** |
| Яндекс | `smtp.yandex.ru` | 465 (SSL) | Яндекс ID → Безопасность → **Пароли приложений** (тип «Почта») |
| Mail.ru | `smtp.mail.ru` | 465 (SSL) | Настройки почты → **Пароли для внешних приложений** |

## Установка на прод одним скриптом

```bash
./scripts/smtp/configure_smtp_on_prod.sh            # настроить
./scripts/smtp/configure_smtp_on_prod.sh --dry-run  # сначала посмотреть, что изменится
```

Скрипт:

1. спрашивает хост/порт/логин/адрес отправителя (подсказки — с дефолтами);
2. пароль спрашивает **скрытым вводом** (`read -s`) и нигде, кроме продового `.env`,
   его не сохраняет — в логах и выводе он замаскирован (`SMTP_PASSWORD=***`);
3. делает бэкап `.env` (`.env.bak.<дата>`, права 600), заменяет только строки `SMTP_*`;
4. переносит бэкенд в свободный слот (синий/зелёный деплой) и перезапускает
   `worker`, затем показывает ответ `/auth/channels/`.

Проверить, что секрет не попал в вывод: `grep SMTP_ /home/…` — в `.env` он есть,
в выводе скрипта и логах — нет.

## После установки

```bash
curl -s https://pismo.space/api/v1/auth/channels/
# {"otp_available":true,"email_otp_available":true}
```

- **Профиль → Безопасность**: появляется «Отправить код на e-mail». Вводишь адрес
  (или сохраняешь его в профиле), получаешь письмо, вводишь код → «E-mail подтверждён»,
  и адрес становится каналом входа и восстановления пароля.
- **Экран входа**: появляются «Войти по коду на e-mail» и «Забыли пароль?».
- Смена адреса в профиле сбрасывает подтверждение — нужно подтвердить заново (так и
  задумано: иначе аккаунт можно угнать через подмену почты).

Если письмо не пришло — смотри лог воркера: при недоступном SMTP код печатается там
(«Почтовая заглушка (dev)»), а ошибки SMTP видны как «SMTP недоступен»:

```bash
ssh -i ~/.ssh/id_rsa1 user1@176.108.249.9 "cd ~/microshop && docker compose -p microshop-test \
  -f docker-compose.test.yaml logs --tail=50 worker"
```

## Про доставляемость (важно для прода)

Отправка через Gmail/Яндекс с личного адреса годится для проверки, но:

- часть писем будет уходить в спам, особенно незнакомым получателям;
- у личных аккаунтов есть суточные лимиты отправки;
- адрес отправителя будет `nyuskov@gmail.com`, а не `pismo.space`.

Для боевого режима лучше домен + транзакционный провайдер (свой `SPF`/`DKIM` для
`pismo.space` и адрес вида `no-reply@pismo.space`): например Brevo/Resend/Mailgun/
Unisender/SendPulse — у большинства есть бесплатный лимит и обычный SMTP, то есть
скрипт подходит и для них (хост/порт/логин/пароль из их панели).
