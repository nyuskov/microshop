### 1. `frontend/src/views/Messenger.vue` — 5139 → 4272 строки (идёт)

Один файл держит каркас, список чатов, ленту, оверлеи, работу с URL и системной
«назад», уведомления. Режем по ответственностям; уже вынесено:

- звонковая обвязка UI ↔ стор — `composables/useCallSession.ts` (экран ожидания
  «Входящий звонок…», системный «будильник», кнопки push, 4 watcher'а);
- URL и системная «назад» — `composables/useChatNavigation.ts` (адрес `?chat=`,
  `pushMobileNav`/`stepBackInApp`, обработка popstate, 3 watcher'а истории) —
  владелец состояния нашёлся именно в composable, `utils/` остались чистыми;
- оверлеи тремя компонентами: каналы (`MessengerChannelOverlays.vue`), «чат и
  группа» (`MessengerChatOverlays.vue`) и «вход и безопасность»
  (`MessengerAccountOverlays.vue`), плюс `MessengerModerationOverlays.vue`
  (жалоба, блокировки, разбор жалоб). Общий приём: состояние диалогов живёт в
  компоненте, наружу — методы `open*`, внутрь — данные, последствия — `emit`.
  Три флага «назад»-контракта (инфо о чате/группе, создание группы) отдаются
  через `v-model`: их читает `useChatNavigation`.
- в канальных оверлеях попутно нашлась и исправлена ошибка: маршрута
  `/c/<адрес>` в роутере не было, ссылка на канал открывала «Страница не найдена».

Осталось (по убыванию пользы):

1. «медиа и пересылка»: пересылка, «Поделиться», истории, лайтбокс, видеозапись.
   Тут вынос дешевле не стал: `storyId`/`lightboxIndex` — тоже шаги «назад»
   (`v-model`), а у «Поделиться» своя цепочка (файл из системного шаринга,
   предпросмотр, отправка) — выносить имеет смысл вместе с ней, а не по частям;
2. непрочитанные/прочитанность — в стор (сейчас ~60 строк размазаны по файлу).

Проверка: тесты `mobileNav`, `chatUrl`, `unreadSeenAtBottom`, `thread`, `call*`,
`channelLink`; плюс сценарии в браузере через CDP — открыть чат → «назад» → профиль
→ «назад»; `?call=…` → экран звонка; `/c/<адрес>` → экран подписки; `?security=1` →
тревога о новом входе; настройки канала из шапки, «Новый канал» и «Новая группа» из
меню сайдбара, модалка удаления из режима выделения.

### 2. `frontend/src/components/messenger/ChatSidebar.vue` — 2600 → 2514 строк

ПРЕПЯТСТВИЕ, из-за которого нельзя просто «вынести разметку»: строки списка и
аватары описаны scoped-стилями самого сайдбара (`.row-item`, `.avatar`, `.row-text`,
`.row-line`, `.row-title`, `.row-sub`). Scoped-стили родителя НЕ применяются к
элементам внутри дочернего компонента (только к его корню), поэтому вынос панели
поиска или контактов в отдельный компонент сегодня = дублирование ~120 строк CSS.

Порядок работ:

1. сначала вынести сами «строки списка» в общий вид — либо презентационный
   `ChatRow.vue` (аватар + заголовок + превью + время), либо общий стиль
   `src/assets/rows.css`, импортируемый в компонентах;
2. потом выносить `SearchPanel.vue` (поле + результаты) и `ContactsPanel.vue`
   (список контактов + импорт из телефонной книги);
3. логика, не зависящая от разметки: `useGlobalSearch` и `useChatSelection.ts`
   (режим выделения: удержание строки, «выбрать все», панель действий) — готовы
   и покрыты тестами; остался `usePhoneImport.ts` (импорт контактов).

Проверка: `slideDown.spec.ts`, `globalSearch.spec.ts`, `chatSelection.spec.ts` +
сценарии в браузере (открытие/закрытие поиска, протяжка списка вниз, прокрутка
вверх, выделение чатов).
