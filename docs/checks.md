# Свои проверки: что делают и когда запускаются

Кроме обычных линтеров и тестов в проекте есть «самодельные» проверки на грабли,
которые ловились руками (мёртвый CSS, светлые пятна в тёмной теме, разъехавшийся
шрифт иконок). Этот файл — карта: что где лежит и что делать, когда проверка
красная.

## Одной командой

```bash
make check            # бэкенд-линтеры + фронтенд (типы, линт, тесты, стили)
make check-backend    # isort / black / flake8 / mypy
make check-frontend   # vue-tsc / eslint / vitest / стилевые скрипты
make test-backend     # pytest на ОДНОРАЗОВОЙ БД в контейнере (безопасно)
make dead-css         # инструмент: кандидаты на удаление мёртвого CSS
```

Это ровно то, что гоняет CI (`.github/workflows/ci.yml`), только без сборки
docker-образов. Если интерпретатор не в `PATH`: `PY=/путь/к/venv/bin/python make check`.

`make test-backend` сам поднимает одноразовую PostgreSQL в контейнере
(`pismo-test-db`, порт 55432), прогоняет миграции и тесты, потом гасит контейнер.
Если в вашем окружении нет `pywebpush` (он есть в CI), цель честно говорит об этом и
пропускает только тесты push — остальное гоняет.

## Только вручную (в CI не годятся)

| Инструмент | Что делает | Почему не в CI |
| --- | --- | --- |
| `frontend/e2e/` (Playwright: `pnpm exec playwright test -c e2e/playwright.config.ts`) | «живое» приложение: экран входа, список чатов и переписка, меню «⋯» с очисткой истории, тумблер приватности присутствия | ходит по НАСТОЯЩЕМУ стенду, а не по сборке; `@playwright/test` намеренно не в зависимостях проекта (иначе тянулся бы в образ), запуск — руками, см. `frontend/e2e/README.md` |
| `node scripts/check-dead-css.mjs` | ищет классы из `<style>`, которых нет ни в разметке, ни в скриптах | есть ложные срабатывания: класс собирается из строки (`error-screen--${tone}`), смотреть глазами |
| `frontend/scripts/build_icons.py` + `fetch_icons.py` | собирают урезанный шрифт иконок и `src/assets/icons.css` | качают исходники Lucide, нужен venv с fonttools/brotli |
| `node frontend/scripts/qa-call-media.mjs` | медиа-тракт звонка в настоящем Chrome: констрейнты захвата, политики ICE, мунж Opus (согласование не ломается), ступени `setParameters`, буферы приёмников, кодеки через `codecId`, уровень речи своим анализатором | нужен Chrome с фейковыми устройствами и поднятый dev-фронтенд (`https://localhost:5173`); так найдены баги, невидимые в jsdom |
| `backend/scripts/cleanup_orphan_media.py` | файлы в `media/`, на которые нет ссылок в БД (по умолчанию dry-run) | нужен доступ к прод-медиа |
| `backend/scripts/make_avatar_thumbs.py` | достраивает миниатюры 128px у старых аватаров | разовая операция на проде |

## Тесты-стражи (в общем прогоне vitest)

Часть проверок живёт тестами, потому что требуют чтения исходников:

- `quasarComponents.spec.ts` / `quasarCss.spec.ts` — все `<q-*>` и `v-*` из шаблонов
  подключены в `src/quasar.ts`, а их стили — в `src/assets/quasar-subset.sass`
  (забытый компонент = пустое место, сборка при этом зелёная);
- `icons.spec.ts` — каждое имя иконки из кода есть в `utils/icons.ts` (иначе Quasar
  нарисует имя текстом);
- `component-imports.spec.ts` — компоненты импортируются так, как ожидается;
- `fontWeights.spec.ts` — в шрифтах есть нужные начертания;
- `slideDown.spec.ts`, `globalSearch.spec.ts` — поведение раскрытия панелей и логика
  поиска (эти два появились вместе с переделкой шапки).

## Проверка на устройстве (то, что не воспроизводится в песочнице)

Часть функций зависит от устройства и браузера, а в среде разработки их нет —
проверяется только руками на живом телефоне/компьютере. Проверять ПЕРЕД релизом:

| Что | Где проверять | Признак успеха |
| --- | --- | --- |
| Расшифровка голосовых и кружков | Chrome на компьютере | кнопка «В текст» есть; запись распознаётся; в подписи нет «не получило звук» |
| Нативное распознавание (Android-обёртка) | Android 13+ | расшифровка идёт без сети; при отсутствии языкового пакета не падает |
| Перевод сообщений | Chrome 138+ на компьютере | модель скачивается по кнопке (нужен жест), затем перевод и «Ещё раз» |
| Push-уведомления | Android (RuStore) и iPhone (PWA на домашнем экране, iOS 16.4+) | уведомление приходит с закрытым приложением; кнопка открывает чат |
| Вид push-уведомления | Android (Chrome/PWA), компьютер | мелкий значок крупный (как в Telegram), аватар отправителя — половина плитки, без аватара — логотип того же размера; кнопки «Ответить» и «Пометить как прочитанное» (на телефоне — после разворота уведомления; на десктопе и iOS кнопки система не показывает вообще) |
| Установка приложения | iPhone (Safari) и Android (Chrome) | iPhone: «Поделиться» → «На экран "Домой"» (в других браузерах установки нет); Android: профиль → «Устройство» → кнопка «Установить приложение» (появляется, только когда браузер готов) либо «⋮» → «Установить приложение»; строка «Открыто: …» называет браузер и путь именно для этого телефона |
| Фото с телефона (HEIC) | Samsung/iPhone: история, чат, аватар | снимок из галереи публикуется и виден с любого устройства (на сервере он стал JPEG), аватар ставится из того же снимка; битый файл даёт понятное «выберите другое» |
| Звонок | два устройства в разных сетях | звук есть (TURN); звонок переживает перезагрузку страницы |
| Показ экрана и эффекты видео | телефон + компьютер | показ включается, камера отключается и возвращается после |
| Тихие часы, звук сообщений, «скрыть текст в уведомлениях» | любое устройство | поведение совпадает с настройками в профиле |
| Чтение без сети (кэш страницы) | любое устройство | включить авиарежим, открыть чат из списка — видны последние сообщения и подпись «Нет сети — показаны сохранённые сообщения»; в профиле → «Хранилище» видно их число |

Проверка идёт по ПЛАТФОРМЕ, а не по наличию API: в мобильном Chrome `Translator` и
`SpeechRecognition` могут быть объявлены, но работать не будут (см.
`utils/browserKind.ts` и `utils/voiceRecognition.ts`). Раздел «Устройство» в
профиле показывает то же состояние, что видит сам код.

## Как обновлять базы

Все «стилевые» проверки сравнивают с базовым файлом и падают только на НОВЫХ
нарушениях. Когда нарушение осознанное и его нужно зафиксировать:

```bash
cd frontend
node scripts/check-tokens.mjs --update-baseline
node scripts/check-style-duplicates.mjs --update-baseline
node scripts/check-geometry.mjs --update-baseline
node scripts/check-bundle-size.mjs --update-baseline     # база снимается с собранного dist
node scripts/check-a11y.mjs --update-baseline            # доступность (eslint-плагин a11y)
node scripts/check-audit.mjs --update-baseline           # уязвимости зависимостей (pnpm audit; нужна сеть)
```

Полезные флаги: `check-style-duplicates.mjs --list` (показать правила по группам),
`--prune` (удалить из `appearance.css` правила-дубликаты), `check-dead-css.mjs <путь>`
(проверить один каталог или файл).

Отдельная база — у стража миграций (бэкенд). Если расхождение метаданных модели со
схемой БД осознанное (autogenerate не умеет описать ручной индекс, комментарий
колонки и т.п.), зафиксируйте его:

```bash
cd backend
python scripts/check_migration_drift.py --update-baseline   # БД должна быть на последней ревизии
python scripts/check_dependency_audit.py --update-baseline  # уязвимости зависимостей (нужна сеть)
```

Снимок схемы API — не «база нарушений», а сам контракт: после осознанной правки
эндпоинтов обновите его и типы фронтенда (иначе CI скажет, что схема разошлась).

```bash
make api-schema                  # backend/openapi.json из текущего кода
cd frontend && pnpm typegen      # src/types/generated.ts из снимка, без сервера
```
