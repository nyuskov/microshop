# Внутренние документы оператора ПДн (шаблоны)

В уведомлении РКН оператор заявляет, что ответственный назначен, перечень данных
определён и оценка вреда проведена. Это значит, что документы должны существовать
у оператора — их может запросить проверяющий. Для оператора-физлица достаточно
решений, подписанных самим оператором: отдельных приказов и печатей не требуется.

Ниже — готовые тексты. Нужно только подставить дату и сохранить (распечатать,
подписать или хранить в виде файла с датой).

## 4. Оценка вреда субъектам персональных данных

> **Оценка вреда, который может быть причинён субъектам персональных данных**
> (ст. 18.1 ч. 1 п. 2 152-ФЗ), от __.__.2026
>
> 1. **Категории субъектов:** зарегистрированные пользователи сервиса Pismo;
>    посетители сайта; лица, обратившиеся по вопросам обработки ПДн.
>
> 2. **Характер данных:** обычные (иные) категории — имя, номер телефона, e-mail,
>    содержимое переписки, технические данные. Специальные категории и
>    биометрические данные не обрабатываются, данные о судимостях не
>    обрабатываются.
>
> 3. **Возможные негативные последствия для субъектов:** доступ третьих лиц к
>    переписке (риск раскрытия личных сведений), использование контактов для
>    спама, попытки входа в аккаунт, потеря доступа к аккаунту.
>
> 4. **Вероятность и тяжесть:** вероятность оценивается как невысокая, тяжесть —
>    средняя: большая часть переписки не содержит чувствительных сведений, для
>    отдельных чатов применяется сквозное шифрование, а доступ к данным имеет
>    только оператор.
>
> 5. **Принятые меры:** см. раздел «Средства обеспечения безопасности» в
>    уведомлении РКН (шифрование канала, хеширование секретов, ограничение частоты
>    запросов, подтверждение входа с нового устройства, журналирование событий,
>    резервное копирование с проверкой восстановления, доступ к серверу по
>    SSH-ключам).
>
> 6. **Вывод:** принимаемые меры соответствуют характеру данных и возможному вреду;
>    дополнительных мер не требуется. Оценка пересматривается при добавлении новых
>    категорий данных или новых целей обработки.
>
> Подпись: ____________ / [И. О. Фамилия] /

## 5. Порядок реагирования на инциденты (краткая памятка для себя)

1. Убедиться в факте инцидента (несанкционированный доступ, утечка, потеря
   носителя): проверить `security_events` в профиле/БД и логи контейнеров
   (`docker compose logs web worker`).
2. Немедленно устранить причину: отозвать сессии (`DELETE /auth/sessions/{id}/`),
   сменить пароли и секреты (см. `docs/jwt-rotation.md`), закрыть доступ.
3. В течение **24 часов** уведомить Роскомнадзор через портал `pd.rkn.gov.ru`
   (форма «Уведомление об инциденте»).
4. Уведомить затронутых пользователей (письмо на подтверждённый e-mail).
5. Зафиксировать: дата, что произошло, что сделано, сколько субъектов затронуто, —
   и хранить вместе с остальными документами.

## Что ещё стоит сделать (не юридическое требование, но укрепляет меры)

- Включить на сервере автоматические обновления безопасности
  (`unattended-upgrades`) и, при желании, `fail2ban` для SSH.
- Открыть порт 5349 и включить TURNS (TLS для релей-сервера) — см. `docs/turn.md`.
