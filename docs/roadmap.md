# Что необходимо доделать в Pismo (приоритеты)

Список составлен 10.09.2026 по итогам разбора кода и прода. Здесь только то, что
реально нужно для работы сервиса, — не «хотелки». Порядок = приоритет.

## P0 — без этого прод хрупкий

1. **Мониторинг и алерты.** Сейчас никакого мониторинга нет: падение сайта,
   кончившееся место на диске или провал бэкапа заметит только пользователь.
   Сделать проверку по cron (HTTP 200 на `https://pismo.space/`,
   `/api/v1/health/ready`, свободное место на сервере, свежесть последнего дампа
   в `~/Документы/pismo_backup`) с уведомлением в Telegram-бот (токен уже есть).
   Оценка: ~1 час.
2. **Смоук-тест прод-API после деплоя в CI.** Сейчас деплой считается успешным,
   если контейнеры поднялись. Добавить шаг после `up -d`: `/api/v1/health`,
   `/api/v1/health/ready`, `/api/v1/auth/channels/`, `alembic current` = ожидаемая
   ревизия; при провале — падать. Оценка: ~30 минут.
3. **Уведомления о критичных действиях аккаунта.** Смена пароля, смена e-mail,
   «выйти на всех устройствах», вход с нового устройства. Сейчас пароль сменили —
   другие устройства молча вылетели, и человек не понимает почему; при угоне это
   единственный сигнал. Канал: e-mail (когда включён SMTP) и/или Telegram.
   Оценка: 2–3 часа.
4. **Довести второй канал доступа.** E-mail-коды уже реализованы, но SMTP не
   задан (`docs/email-smtp.md`), а SMS Aero без договора (ИП/ООО) отклоняет все
   SMS. Итог: у кого нет Telegram — ни регистрации, ни восстановления пароля.
   Требуется: SMTP-данные + решение по договору с SMS Aero.

## P1 — требует сам продукт

5. **2FA на новых устройствах + список активных сессий** с отзывом по одной.
   Устройства запоминаем (cookie + запись в БД), при входе с нового — код в Telegram
   (~2,49 ₽ только на новых устройствах).
6. **Квоты на медиа.** Сейчас ограничен только размер одного файла (15 МБ) и
   частота загрузок; накопление ничем не ограничено. Нужно: квота на пользователя
   (например 500 МБ), автоочистка файлов без ссылок в БД (есть
   `scripts/cleanup_orphan_media.py`), алерт по свободному месту.
7. **Модерация: автоматика и журнал.** Счётчик жалоб на пользователя, авто-скрытие
   контента после N жалоб, журнал «кто/когда/какой статус/заметка», уведомление
   заявителю. RuStore требует разбора UGC — сейчас всё вручную и без следа.
8. **Правила сообщества (Community Guidelines).** Для UGC-приложения магазины
   требуют не только политику конфиденциальности; добавить страницу и ссылку в
   приложении/профиле.
9. **Уведомление в РКН об обработке ПДн** (юридическое требование, не код).
10. **Проверить push на iOS/PWA.** На Android (RuStore) push есть; для iPhone в
    PWA нужно убедиться, что Web Push работает (iOS 16.4+, добавление на домашний
    экран). Для мессенджера отсутствие уведомлений критично.

## P2 — эксплуатация и разбор инцидентов

11. **Аудит-лог безопасности** (вход, смена пароля/e-mail, отзыв сессий, неудачные
    входы) в БД или лог — для ответа на вопрос «что происходило с аккаунтом».
12. **Автопроверка бэкапа** — раз в неделю разворачивать последний дамп в тестовую
    БД и проверять читаемость + совпадение ревизии миграций, при ошибке — алерт.
    (10.09.2026 такая проверка вручную прошла: `users=5`, ревизия
    `e3f4a5b6c7d8` — совпало с продом.)
13. **Ротация JWT-секрета без потери данных** (версионный секрет, план ротации):
    сейчас при утечке ключа access-токены (30 мин) валидны, отозвать их нельзя.

## Сознательно отложено

- E2EE с forward secrecy и шифрование медиа, групповые звонки — большие отдельные
  проекты (недели), не блокеры.
- Регистрация по e-mail вместо телефона — решение осознанное (номер остаётся
  основой аккаунта).
