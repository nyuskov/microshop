### Запуск и проверки

```bash
cd frontend
pnpm install
pnpm dev            # Vite dev (HTTPS :5173)
```

Проверки (нужно запускать **бинарники напрямую через node**, т.к. shims из `.bin/*` могут падать из-за прав `node_modules`):

```bash
node node_modules/vue-tsc/bin/vue-tsc.js --build --force   # типы
node node_modules/eslint/bin/eslint.js --no-cache src      # линт
node node_modules/prettier/bin/prettier.cjs --write <files> # формат
```

`package.json`-скрипты: `dev`, `build`, `type-check`, `lint`, `format`, `test:unit` (vitest).

Проверки в dev **никогда не роняют сайт** (важно для работы с телефона/в браузере):

- eslint-плагин Vite работает в режиме `failOnError: false` — ошибки линта печатаются в лог dev-сервера (и не прерывают загрузку модуля, иначе в браузере был бы белый экран вместо приложения);
- плагин `vite-plugin-checker` показывает ошибки типов **бейджем внизу справа** (`overlay: { initialIsOpen: false, position: 'br' }`) — панель раскрывается по клику и ничем не закрывает интерфейс;
- `server.clearScreen: false` — лог не стирается на каждой пересборке, предупреждения видно «внизу» терминала.

В CI проверки остаются строгими (`.github/workflows/ci.yml`): `vue-tsc --noEmit` и `eslint --no-cache src` запускаются отдельными шагами и падают с ошибкой. Смягчение только в dev-режиме Vite — чтобы правка не оставляла без сайта до следующего коммита.

### Экраны ошибок (404 / 500)

Пользователь никогда не должен видеть пустой экран или голый текст ошибки браузера:

- **внутри приложения** — маршрут `/:pathMatch(.*)*` рисует `views/NotFound.vue` («Страница не найдена» в стиле приложения с кнопками «К чатам»/«Назад»); фатальные ошибки рендера/обработчиков ловят `main.ts` (`app.config.errorHandler` + `window.onerror`) и показывают `FatalErrorScreen.vue` с перезагрузкой;
- **статически** — `public/404.html` и `public/500.html` (одна палитра с приложением, без внешних ресурсов и service worker'а). Их отдаёт nginx: `error_page 404 =404 /404.html` (нет файла/ассета — статус остаётся 404) и `error_page 500 502 503 504 =500 /500.html`. Ответы `/api/` и `/media/` не перехватываются (`proxy_intercept_errors` выключен), поэтому JSON-ошибки бэкенда уходят клиенту как есть.

### Уведомления внутри приложения (Notify)

- `Notify.create` — только для **ошибок и предупреждений**: без плашки непонятно,
  почему действие не выполнилось («Не удалось отправить», «Файл слишком большой»,
  «Откройте чат, чтобы отправить файл»).
- **Успех молчит.** Результат и так виден в интерфейсе: папка появилась в списке
  чипов, сообщение — в ленте, канал сохранился и диалог закрылся. Отдельного
  «Папка создана» быть не должно (правило с 2026-09-18, см. `docs/changelog.md`).

### Отложенные сообщения («отправить позже»)

- Меню времени живёт **на самой кнопке отправки** (`MessageComposer.vue`):
  обычный клик отправляет, удержание (телефон) или правая кнопка (компьютер)
  открывают «Через час / Сегодня в 9:00 / Завтра в 9:00». Отдельной кнопки нет —
  она бы дублировала основную. Пункты считаются от текущего момента: вечером
  «сегодня в 9:00» не предлагается.
- Шторка `components/messenger/ScheduledBar.vue` над полем ввода показывает
  очередь **этого чата**: счётчик, ближайшее время, раскрытие со списком и отмена
  каждой записи. Содержимое выровнено по центру полосы (`justify-content: center`
  + `align-items: center`), как в шторке закреплённых.
- Очередь разбирает сервер (`tasks/scheduled_tasks.py`, beat раз в минуту), поэтому
  сообщение уходит и с закрытым приложением; клиент знает только про
  `send_at` (UTC) и ничего не таймерит.
- В E2EE-чате текст шифруется до отправки, а для превью в шторке расшифровывается;
  если ключа нет — «Зашифрованное сообщение» (шифротекст не показываем). Очередь
  перечитывается при открытии чата (`loadScheduled`) и сбрасывается при переходе
  в другой.

### Связь (нет сети / соединение)

Плашка сверху, полосой во всю ширину — как «Соединение…» в Telegram. Состояния:
серая «Нет подключения к интернету» (с подсказкой «сообщения отправятся, когда
связь вернётся»), «Соединение…» со крутящейся иконкой, пока приложение добирает
пропущенное, и зелёная «Связь восстановлена» (2.5 с). Пока плашка видна, баннер
«Доступна новая версия приложения» сдвигается вниз (`.pwa-update-bar.shifted`),
чтобы они не перекрывались.

- Связь определяется **ответом сервера** (`GET /system/ping/`, `services/system.ts`),
 а не событиями браузера: `navigator.onLine` говорит только про сетевой
 интерфейс. Маяк идёт через `fetch` (не через общий axios — не нужны
 интерцепторы, нужен короткий таймаут 4 с) и не кэшируется; любой ответ,
 включая 5xx, означает «связь есть».
- Частота — в `composables/useOnlineStatus.ts`: 2 секунды, пока связи нет, и 15
 секунд в обычном режиме (частый маяк будил бы радио на телефоне). События
 браузера и сетевые ошибки API (`services/api.ts` → `reportConnectionLost`)
 дают мгновенную реакцию; возвращение на вкладку — тоже повод проверить.
- Состояние одно на приложение (refcount в composable), поэтому
 `OfflineBanner` в `App.vue` и `Messenger.vue` делят один таймер пинга.
- Когда связь вернулась, composable бросает `pismo:connection-restored`:
 мессенджер досылает очередь «Ждёт сети», перечитывает чаты, открытую переписку
 и истории, а флаг догрузки держит плашку в состоянии «Соединение…» (страховка
 10 с).

### Ключевые точки

- `main.ts` — Quasar 2 (Dialog/Notify, lang ru, **Material Symbols Rounded** — `@quasar/extras/material-symbols-rounded`; Quasar рендерит `<q-icon>` с классом `.material-icons`, на него в `quasar.css` повешен алиас шрифта), тема/оформление через `stores/theme.ts` (`data-theme`, токены `--ms-*`; тема ставится ДО первого кадра inline-скриптом в `index.html`, чтобы не мигала; темы — светлая, тёмная, «по системе», «по расписанию» и **AMOLED** — флаг `amoled` в состоянии, уточнение тёмной: `html[data-theme='amoled']` даёт чистый чёрный фон окна и ленты, а «поднятые» поверхности остаются чуть светлее), инициализация auth.
- Расписание тёмной темы: режим `mode: 'schedule'` и границы `darkFrom`/`darkTo` (минуты от полуночи, шаг час) — правила в `utils/themeSchedule.ts` (`isDarkBySchedule`, `msUntilScheduleChange`, `scheduleSummary`), окно может идти через полночь. Тема не опрашивает часы каждую минуту: `stores/theme.ts::planScheduleCheck` ставит один таймер на ближайшую границу, а `watchSchedule` пересчитывает тему при возврате в приложение (`visibilitychange`) — телефон в фоне замораживает таймеры. Совпавшие границы считаются выключенным расписанием, иначе «с 00:00 до 00:00» запереть в тёмной теме на сутки. Настройка — в разделе «Внешний вид» (два списка `SelectField`: «Тёмная с» и «до»); следит `__tests__/themeSchedule.spec.ts`.
- Оформление: токены тем `--ms-*` + `color-scheme` и глобальные оверрайды над scoped-стилями — в `assets/appearance.css`; `assets/quasar.css` приводит Material-компоненты к токенам; базовая геометрия кнопок (`.icon-btn`/`.round-btn`) — общая в `appearance.css`; «пустые состояния» — общий компонент `components/common/EmptyState.vue`. Полей с родными контролами браузера нет: выпадающие списки — `components/common/SelectField.vue` (свой слой с расчётом координат, `utils/select.ts`), дата — маскированный ввод `ДД.ММ.ГГГГ` (`utils/dateInput.ts`); следит `__tests__/nativeControls.spec.ts`.
- Серии сообщений (подряд идущие сообщения одного автора): границы считает `utils/thread.ts::seriesKindFor` (тот же автор + пауза < 5 минут; разделитель дня разрывает серию), `MessageThread` отдаёт `series: single|first|middle|last` в `MessageRow` — от этого зависят скругления пузыря (срез только у первого) и отступы, им же определяется имя автора в группах.
- **Типографика**: служебный текст (время сообщения, плашка статуса, счётчики, подписи диалогов) берёт размер из шкалы `--ms-fs-*`, и каждое её значение умножено на `--ms-text-scale` — поэтому настройка «Размер текста» (мелкий/обычный/крупный) двигает и подписи, а не только сообщения и список чатов. Фиксированные `font-size` мельче 12px запрещены; для тесных мест (кружок пересылки 18px, «+» в кружке истории 14px) допустим `calc(Npx * var(--ms-text-scale, 1))`. Следит за этим `__tests__/smallText.spec.ts`.
- **Тач-таргеты**: до 600px кнопки `.icon-btn`/`.round-btn` — 38px (было 32–34), в шапке чата и композере остаются ровно такими же (своих уменьшающих медиазапросов у них больше нет): при 30px и зазоре 2px палец попадал в соседнюю кнопку. Чипы фильтров остаются компактными (пять должны влезать в 390px) — у них расширена только область нажатия (`::after` с `inset: -4px -2px`), сам размер не изменился.
- PWA/иконки: `public/favicon.svg` (градиентная «письмо-пузырь»), PNG-набор `public/icons/` (`icon-192`, `icon-512`, `icon-maskable-512`, `apple-touch-icon-180`, `badge-96`) + `manifest.webmanifest` (name/short_name Pismo, `theme_color #5a50e0`). ### Экраны

- `Messenger.vue` — адаптивный Telegram-подобный вид: `q-layout` + `q-drawer` (панель «Чаты/Контакты»). Раскладка по ширине окна: **< 600 px — телефон** (список и нить на одном экране, drawer поверх чата, навигация по истории приложения — `utils/mobileNav.ts`, кнопка «назад» в шапке), **600–1023 px — планшет** (две панели: список 320 px + нить), **≥ 1024 px — десктоп** (две панели, список 380 px). В коде это `isPhone = $q.screen.lt.sm`, `isDesktop = $q.screen.gt.sm` и `twoPane = !isPhone` (от последнего зависят история приложения и возврат к списку; `$q.screen` меняется динамически при повороте экрана). Дальше: список диалогов (пины/онлайн/«печатает…»), окно чата (пузыри вправо/влево, day-разделители, reply-цитата, закреплённые сверху, файлы/картинки, реакции, hover-действия, inline-поиск по сообщениям). Модалка «Настройки» (`UserProfile`) — список разделов (Аккаунт, Безопасность, Приватность, Уведомления, Хранилище, Внешний вид, О приложении); оформление (`AppearanceSettings`) встроено в раздел «Внешний вид». Ниже десктопа окно настроек полноэкранное (`:maximized` у `q-dialog` + класс `.ms-modal-full`): карточка оставляла по краям полоски чата и два вложенных скролла, теперь прокрутка одна — `.ms-modal-body`. Ещё модалки: «Информация о чате» (`ChatInfo`), вход (`LoginModal`), лайтбокс изображений (`ImageLightbox`). На широком экране (≥ 1280 px) «Информация о чате/группе» показывается правой колонкой 340 px рядом с перепиской (`.chat-rail`, режим `panel` у `ChatInfo`/`GroupChatInfo` — та же карточка без рамки, прокрутка внутри), открыть/закрыть — клик по названию чата или пункт «Информация о чате» в «⋯»; каналы остаются в модалке. Обновления — WS-события + fallback-polling 20 с.
- **Админская панель** (только аккаунт с `is_superuser`): «шестерёнка» внизу слева в списке чатов (`ChatSidebar`, `.admin-gear`) открывает настройки сразу на экране «Администрирование». Там собраны служебные разделы: «Приглашения» (`InvitesSettings.vue` — создать ссылку, скопировать/поделиться, отозвать) и «Жалобы» (диалог модерации открывается через `emit('open-moderation')` — сам диалог живёт в `MessengerModerationOverlays`). Из меню «⋯» и из обычных настроек эти пункты убраны. Начальный экран настроек передаётся пропом `start-section`: профиль грузится отдельным чанком, и на первом открытии вызов `profileRef.openAdmin()` не долетает — компонента ещё нет.
- **Согласие при регистрации**: `components/common/ConsentCheckbox.vue` — обязательная галка на шаге подтверждения кода для нового номера и на шаге создания пароля (плюс `InviteRegister`). При обычном входе галки нет. Факт согласия уходит в запрос регистрации (`accept_terms`).
- **Поле телефона**: `components/common/PhoneInput.vue` — единое поле для входа, приглашения и профиля; ввод разбирается целиком (`localPhoneDigits`) и форматируется в маску, каретка остаётся на той же цифре. У `q-input` id поля задаётся пропом `for` (иначе `<label for=…>` не связан с полем).
- `UserProfile.vue` — редактирование профиля + аватар (клик по аватару → выбор файла, удаление фото, кнопка «Выйти»); телефон — только для чтения (логин аккаунта, класс `.readonly-field`), в запрос обновления не отправляется.
- **Блокировка собеседника** (меню «⋯» в шапке личного чата): «Не принимать звонки» / «Принимать звонки» (мягкая блокировка — переписка и чат остаются) и «Заблокировать» / «Разблокировать» (полная: переписка запрещена, чат скрыт). Состояние читается с сервера (`GET /moderation/blocks/{id}/`) — иначе подписи врали бы после перезагрузки; следим и за id чата, и за появлением чата в списке (открытие по `?chat=`). Экран «Заблокированные» показывает вид («· только звонки») и даёт переключить его на месте.
- **Тихие часы** (раздел «Уведомления»): тумблер «Тихие часы», два поля времени («С»/«До», шаг 30 минут — `utils/quietHours.ts::timeOptions`, списком `SelectField`, без родного `<input type="time">`) и тумблер «Разрешить звонки». Сохраняется сразу при изменении (PATCH профиля), под тумблером — человеческая подпись («Не беспокоить с 23:00 до 08:00 (через ночь); звонки разрешены») и местный пояс. Время — минуты от полуночи, а сдвиг пояса берётся у устройства в момент сохранения (`localUtcOffsetMinutes()`): сервер про пояс ничего не знает. Тумблер тихих часов приглушён, пока выключены сами уведомления. Решает сервер (`core/quiet_hours.py`) — см. `docs/backend.md`.
- **Текст сообщения в уведомлении**: тумблер «Показывать текст сообщения» там же (раздел «Уведомления», сохраняется сразу, как приватность; приглушён при выключенных уведомлениях). Выключен — в push останется только имя отправителя; решает сервер (`notification_preview` в профиле).
- **Меню «⋯» в шапке чата**: поиск по сообщениям, «В архив» (локально), «В папку…» (отметить папки, где виден чат), «Звук уведомлений» (`ChatSoundDialog.vue`: пять синтезированных пресетов + «Как в остальных чатах», настройка устройства в `pismo_chat_sounds`), «Статистика чата» (`ChatStatsDialog.vue` — итоги, 30 дней, топ участников, вложения; считает `GET /chats/{id}/stats/`), показ/скрытие шторки закреплённых (пункт есть только когда закреплённые есть), а для личных диалогов — жалоба и блокировка.
- **Шторка «Закреплённые сообщения»** (`PinnedBar.vue`): отдельная строка над лентой, где булавка, заголовок, круглый счётчик и стрелка центрированы по вертикали (`align-items: center` + фиксированная `min-height` — иначе при одной строке текста заголовок «плавал»). Заголовок со стрелкой раскрывает и сворачивает список (поворот стрелки гасится при `prefers-reduced-motion`), крестик скрывает шторку целиком, клик по элементу списка прокручивает ленту к сообщению и подсвечивает его. Крестик — не дорога в один конец: шторка возвращается пунктом «⋯» → «Показать закреплённые» (тот же пункт скрывает — «Скрыть закреплённые»), при возврате список раскрывается сразу. Скрытие живёт до смены чата (`pinnedHidden` сбрасывается при открытии диалога).
- **Экран «Звонки»** (пункт «Звонки» в меню «⋯» списка чатов, `CallHistoryDialog.vue`): записи о звонках всех личных чатов одним списком — разделители дней, фильтр «Все/Пропущенные», «Перезвонить» тем же типом звонка и переход в чат по нажатию. Данные — `GET /calls/history/` (страницами по 50, «Показать ещё»), правила показа — `utils/callHistory.ts`; чанк ленивый (`defineAsyncComponent`).
- **Папки чатов** (свои списки с ручным порядком, как в Telegram): чипы после базовых фильтров, кнопка «+» в конце ряда, управление папкой — долгий тап по её чипу или правый клик (`ChatList.vue` → `ChatFoldersDialog.vue`: состав, порядок кнопками ↑/↓, переименование, удаление с подтверждением), а пункт «В папку…» в меню чата и кнопка в панели выделения открывают `ChatFolderPicker.vue` (галочки применяются сразу). Хранится локально (`pismo_chat_folders`, разбивка по id пользователя) — сервер о папках не знает; правила и правки — в `utils/chatFolders.ts` + `composables/useChatFolders.ts` (состояние одно, чтобы список и диалоги не расходились). Архивированный чат не виден и в папке: архив остаётся отдельным измерением. В папке порядок ручной (пины не поднимают чат наверх), «Сохранённые сообщения» в папки не добавляются. Ряд чипов листается колесом, свайпом и перетаскиванием мышью (стрелки отвергнуты как лишние), выбранная папка подкручивается в видимую часть.
- **Просмотр историй** (`StoryViewer.vue`): тап по центру ставит быструю реакцию (эмодзи с вспышкой), края листают; на чужой истории снизу есть поле «Ответить <имя>…» — ответ уходит сообщением в личный чат автора со снимком истории (`reply_to_story` в `types/index.ts`), просмотрщик при этом не закрывается. Плашка в ленте — `.story-reply` в `MessageRow.vue` (миниатюра + подпись, живёт и после удаления истории).
- **Проверка ключей шифрования** (safety number): в разделе «Сквозное шифрование» карточки `ChatInfo.vue` кнопка «Проверить шифрование» открывает `SafetyNumberDialog.vue` — код из 12 групп по 5 цифр, одинаковый у обоих участников. Считается на устройстве: `services/e2ee.ts::safetyNumberWithPeer` берёт публичные ключи обоих, приводит их к каноническому виду (`utils/safetyNumber.ts::canonicalKey` — иначе JSON с другим порядком полей дал бы другой код), сортирует (`orderKeys`) и хеширует `SHA-512`; 60 байт превращаются в группы по 5 цифр. Серверу ничего не отправляется, отметка «проверено» не хранится: ключ привязан к устройству, и при входе с нового сверять надо заново (в диалоге об этом написано). Кнопки нет у «Сохранённых сообщений» и при выключенном E2EE — сверять не с кем и нечего.
- **Своё устройство** (`utils/deviceId.ts`): идентификатор устройства генерируется в браузере и живёт в `localStorage` (`pismo_device_id`) — сервер по нему только различает ключи E2EE, никакой связи с человеком он не несёт. Вместе с публичным ключом он уходит в `PUT /keys/me/`, поэтому вход с телефона больше не затирает ключ компьютера (A5). На устройстве, где ключ уже есть, а метки нет (вход прежним клиентом), остаётся `legacy`: иначе тот же ключ записался бы второй строкой и у собеседника появилось бы лишнее устройство. Выход из аккаунта метку НЕ удаляет — это свойство устройства, а не сессии. Метку `legacy` получали и свежие установки (она ставилась уже после генерации ключа — исправлено 18.09.2026), поэтому сохранённая `legacy` переводится на свой идентификатор: иначе телефон и компьютер делили бы одну строку ключа.
- **Резервная копия ключа шифрования** (F2, 18.09.2026): профиль → «Безопасность» → «Ключ шифрования» (`E2eeBackupDialog.vue`, ленивый чанк) — сохранить копию/восстановить. Файл собирает `services/e2eeBackup.ts`: ключ устройства, зашифрованный AES-GCM, ключ из парольной фразы через PBKDF2-SHA256 (210 000 итераций). Копия хранит и метку устройства (обёртки чатов привязаны к паре «устройство + ключ»), поэтому после восстановления приложение перезапускается и перечитывает переписку.
- **Ключ личного чата — по устройствам** (`services/e2ee.ts`, 18.09.2026): личный чат шифруется симметричным ключом чата, а на сервер уходят обёртки — этот ключ, зашифрованный общим секретом конкретной пары устройств (`chat_device_keys`, `GET/PUT /keys/chat/{chat_id}/`). Включение E2EE раздаёт ключ (`distributeChatKey`), открытие чата добавляет обёртки для новых устройств (`refreshChatKeyWrappers`), расшифровка перебирает симметричный и прежний ключ (`chatDecryptKeysFor`) — поэтому телефон и компьютер читают одну переписку, а история, зашифрованная до A5, остаётся доступной.
- **Групповой звонок «mesh» (до 4 человек)**: кнопка звонка есть и в групповом чате (в каналах и «Сохранённых сообщениях» — нет). Каждый участник держит своё соединение с каждым (`runtime.links` в `stores/call/signaling.ts`), медиа идёт напрямую — поэтому сквозное шифрование сохраняется. Кто с кем соединяется, решает правило «младший по id инициирует»: одновременные offer от обеих сторон (glare) сорвали бы соединение. Состав звонка присылает сервер (`call-peers`), а лимит в четыре человека проверяют и клиент (`MAX_GROUP_PARTICIPANTS`), и сервер. Интерфейс — сетка плиток (`components/calls/CallGrid.vue`): у каждого участника свой поток, имя, индикатор микрофона и значок показа экрана. Пока звонок не принят, соединения не поднимаются — иначе собеседники решили бы, что человек уже в разговоре.
- **Групповой вызов начинается с первым ответившим**: ждать, пока поднимут все трубки, не нужно — инициатор сразу видит сетку (`CallGrid` показывается и в исходящем вызове), у неподключившихся плитка «Звоним…», а как только кто-то ответил — разговор идёт, остальные продолжают звонить (их входящий продлевается, пока звонок жив) и присоединяются при ответе (`_syncMesh` соединяет нового участника со всеми). Неответившего можно **сбросить** кнопкой на его плитке (`call-drop`): сервер убирает его из состава и гасит у него окно вызова. Завершение и отмена в группе уходят ВСЕМ участникам набора — иначе остальные продолжали бы звонить.
- **Плитка участника показывает видео по живому треку** (`remoteHasVideo` в `stores/call.ts`, `hasLiveTrack` в `stores/call/media.ts`): флаг `videoOn` из сигналинга приходит отдельным сообщением и может отставать, поэтому решение принимается по дорожке потока, а признак пересчитывается по её событиям `mute`/`unmute`/`ended`. Иначе проверка выполнялась один раз — до того, как удалённый трек снимется с `muted`, — и плитка навсегда оставалась с аватаром («видно только своё видео»).
- **Звук идёт одним путём**: в групповом звонке звук собеседников играет Web Audio (`stores/call/output.ts` держит СПИСОК источников — слышны все, ушедший вынимается), а элементы плиток (`CallGrid.vue`) глушатся, пока Web Audio готов; иначе речь звучит дважды с задержкой и «расплывается». Громкость меняется плавно (30 мс), мгновенная смена щёлкает. В одиночном звонке так же глушатся `remote-video`/`remote-audio`.
- **Кандидаты ICE не теряются**: в сообщении `ice-candidate` уходит сам кандидат (`event.candidate.toJSON()`), а пришедшие раньше создания соединения (у абонента телефон ещё звонит, а зовущий уже собрал адреса) складываются в `runtime.pendingCandidates` и отдаются соединению сразу после применения SDP собеседника (`_addCandidate`/`_flushCandidates`). Без этого ICE оставался в состоянии `new` и медиа не шло вовсе.
- **Качество звонка на плохой сети** (`stores/call/quality.ts`): в SDP включаются помехоустойчивые параметры Opus (`minptime=20;useinbandfec=1` — потери до ~20 % восстанавливаются избыточностью, `stereo=0;sprop-stereo=0` — моно, `maxaveragebitrate=48000`). DTX (`usedtx`) и 10-мс пакетирование СОЗНАТЕЛЬНО не включаем: экономия тишины слышна щелчками и «бульканьем» на стыках фраз, то есть теми самыми искажениями. Всё остальное задаёт ОДНА ступень качества (`qualityStepFor` — good/fair/bad по потерям в оба направления, включая `remoteLossPercent` — это наш аплинк, — дрожанию, задержке и оценке доступной полосы `availableOutgoingKbps`): битрейт видео 700/350/140 кбит/с, битрейт звука 48/32/24 кбит/с, разрешение (`scaleResolutionDownBy` 1/1,5/2) и частота кадров 30/24/15 — таблицы в `senderTuningForStep`. Ступени применяются к КАЖДОЙ связи (`_tuneLinksByStats`: в группе у собеседников качество разное, одна общая ступень резала бы видео всем по худшему); ухудшение — сразу, улучшение — только выждав 15 с (`resolveStep` + `QUALITY_STEP_COOLDOWN_MS`), иначе на границе порогов ступень «дышит» каждый опрос. У звука `priority: high`, у видео — `low`, поэтому при перегрузке режется картинка, а не разговор; при нехватке полосы падает разрешение, а не частота кадров (`maintain-framerate`), у показа экрана наоборот (`maintain-resolution` + `contentHint: "text"`, 1,2 Мбит/с и 15 к/с — ступени сети на экран НЕ действуют, иначе текст становится нечитаемым). Подсказки кодеку: речь / движение / текст.
- **Буфер воспроизведения и видео-пауза**: приёмникам ставится цель буфера (`tuneReceivers`: 50–140 мс звук, 200–700 мс видео, растёт с дрожанием) — буфер «с запасом», который браузер выбирает сам, давал ощутимую задержку разговора. Если связь плоха три опроса подряд (≈15 с: потери 8 %+, дрожание 90 мс+, задержка 600 мс+), видео приостанавливается (`pauseVideoForNetwork`: дорожки снимаются у всех связей, собеседник видит аватар, звук остаётся) и возвращается после пяти хороших опросов, кнопкой камеры или пунктом «Вернуть видео»; передатчики запоминаются в `runtime.pausedVideoSenders` — после `replaceTrack(null)` найти их по дорожке нельзя.
- **Захват медиа — с «планом Б»** (`stores/call/media.ts`): звук просим с эхоподавлением, шумодавом, автоуровнем, моно, 48 кГц, минимальной задержкой и `voiceIsolation`; режим обработки («Чистый голос» / «Естественный») выбирает человек, смена режима перезапрашивает микрофон (`setMicProcessing`), а старая дорожка гасится только после успешной замены. Камера пробуется «лестницей» 640×480@24 → 480×360@20 → 320×240@15 и лишь потом звонок идёт без видео (`acquireLocalMedia` + `_applyAcquiredKind`): раньше `OverconstrainedError` на дешёвом Android заканчивался отказом, хотя разговаривать было можно. Запрет доступа и «камера занята» форматы не перебирают, а устройство из настроек требуется только в первой попытке. В группе захват сразу меньше (480×360@20) — поток уходит каждому участнику.
- **Индикатор говорящего**: уровень речи измеряется СВОИМ анализатором (`output.ts`: `AnalyserNode` перед громкостью, `rmsLevel`, `remoteLevels`) — Chrome отдаёт `audioLevel` только когда звук выводится элементом, а в группе звук идёт через Web Audio, и там он нулевой (проверено живьём). Флаг — с двумя порогами (`speakingNow`: 0.01 на включение, 0.004 на выключение — с одним порогом кольцо мигало бы на паузах между словами); плитка участника подсвечивается кольцом (`outline`, а не `border`: рамка меняет размеры и двигала бы соседние плитки).
- **Каждый удалённый поток всегда привязан к элементу** (в 1:1 — один `<video>`, который в аудиозвонке и при выключенной камере просто невидим; в сетке — `<video>` на каждой плитке, скрытый классом `grid-video-hidden`). Это не про картинку: только привязанный поток Chrome отдаёт в Web Audio, иначе звук и измерение уровня пропадают (найдено живой проверкой 18.09.2026: без элемента уровень 0, с заглушённым элементом наш анализатор видит 0,355).
- **Группа решает по-групповому**: диагностика показывается СТРОКОЙ НА КАЖДОГО участника (`peerQualityLine` — задержка, потери приёма, потери нашего потока на его стороне, ступень; реактивная копия — `peerDiagnostics`), бейдж «Плохая связь» загорается по ХУДШЕЙ связи (`worstQuality`), а пауза видео — только когда плохо больше половины связей (`shouldPauseForQuality`): один собеседник в метро не должен гасить картинку остальным.
- **Плашка звонка — верхняя строка**: имя/таймер/маршрут (`CallOverlay.vue`) идут отдельным рядом сверху, под ними — картинка (плитки в группе) и внизу — кнопки; в групповом вызове «Звоним…» с «Отменить» занимает ту же верхнюю строку (`group-stage`), плитки — под ней. Раньше плашка была слоем поверх плиток и закрывала у верхних кнопку сброса участника.
- **Групповой звонок не рвётся из-за неподключившихся**: отказ или выход одного участника убирает только его плитку (`_dropParticipant`), а разговор продолжается — пока в звонке есть хоть одна живая связь. Лимит попыток перезапуска ICE считается **на связь** (`PeerLink.iceRestartAttempts`), иначе неудачи одного собеседника (вышел из сети, экзотический NAT) расходовали бы общий лимит и «Связь потеряна» гасла бы у всех. Наблюдатель медиа в группе довольствуется тем, что слышно хотя бы кого-то, и перезапускает ICE только «молчащим» связям.
- **Звонок: код сверки и честный бейдж** (`CallOverlay.vue`, `utils/callVerification.ts`): бейдж показывает маршрут медиа — «Напрямую (P2P)» или «Через релей» (по `candidateType` из `getStats`), а в подсказке сказано, что при релее шифрование сохраняется (TURN видит только шифротекст). Пункт меню «Код сверки» показывает 6 цифр, одинаковых у обоих участников: `stores/call.ts::refreshVerificationCode` берёт отпечатки сертификатов DTLS (`a=fingerprint:sha-256`) из локального и удалённого SDP, сортирует их и хеширует — подсунутый сертификат даёт другой код. Код относится к конкретному соединению и сбрасывается при завершении звонка.
- `Login.vue` / `LoginModal.vue` — вход по номеру: шаги `phone → password | otp → create` (автофокус поля), исходя из `password/status`; `LoginModal` держит диалог открытым после подтверждения кода (`pendingPassword`), пока пользователь не задаст пароль.
- **Реакции — как в Telegram** (`MessageRow.vue` + `ReactionUsersDialog.vue`): чипы живут ВНУТРИ пузыря — нижний ряд `.msg-footer`, где реакции слева, а время справа; рамок у чипа нет, «своя» реакция выделяется полупрозрачным тоном. Пока отметивших не больше трёх, в чипе видны их мини-аватарки (дальше — счётчик). Тап ставит/снимает свою реакцию, удержание (450 мс) или правый клик открывает окно «Кто поставил» — всплывающее (`q-menu`), привязано к чипу и раскрывается снизу. Новая реакция «выстреливает» эмодзи и ореолом (класс `fresh` ставится по росту счётчика, поэтому снятие и первая отрисовка ленты не мигают). Эмодзи в сообщении мелкий (`--ms-fs-md`), в окне списка — крупный.
- **Подсветка перехода и выделение сообщений** (`MessageThread.vue`): полоса во всю ширину чата ПОД сообщениями (полупрозрачный тон, `.highlight-band`) — вспышка на 2.4 с при переходе к закреплённому/из поиска и постоянная у выбранных сообщений. Фон пузыря при этом не подсвечивается, рамок нет ни у пузыря, ни у шторки закреплённых (та отбивается только фоном).
- Компоненты мессенджера вынесены в `components/messenger/` (`ChatSidebar`, `ChatHeader`, `MessageThread`, `MessageRow`, `MessageComposer`, `PinnedBar`, `InlineSearchBar`, `ChatPlaceholder`, `ChatInfo`, `ForwardDialog`, `FileDropOverlay`); медиа — в `components/media/` (лайтбокс, голос/видео/кружки, GIF-пикер); звонки — `components/calls/`. Недоступное видеосообщение (`RoundVideoMessage`, класс `broken`) рисуется компактной плашкой в токенах темы (`--ms-surface-2`/`--ms-muted`), а не кругом 300px с чёрной подложкой; у него нет `role="button"` и кнопки плавающего окна — играть нечего. Реактивное присутствие/печать — `composables/usePeerActivity`, realtime-оркестрация — `composables/useRealtimeSync`, запись — `useRecordButton`, перетаскивание файлов в окно — `useFileDrop` (слушатели на `window`: бросить файл можно в любое место, `preventDefault` не даёт браузеру открыть файл вместо чата).
- Новый компонент Quasar в разметке — это ДВА дела: регистрация в `src/quasar.ts` и импорт его sass в `src/assets/quasar-subset.sass`. Забыть можно незаметно (Vue молча отрисует неизвестный тег, а компонент без стилей выглядит «голым») — от этого стоят стражи `quasarComponents.spec.ts` и `quasarCss.spec.ts`.

### Эмодзи и стикеры

**Эмодзи — весь набор Unicode, по категориям, без «паков».** Панель в композере
показывает полоску значков-категорий (🕒 недавние, далее Смайлы, Люди, Природа,
Еда, Места, Занятия, Предметы, Символы, Флаги) — как системная клавиатура и
Telegram. Внутри категории — все эмодзи группы.

Каталог **генерируется**, а не пишется руками:

| Шаг | Что делает |
| --- | --- |
| `scripts/build-emoji-catalog.py` | скачивает `emoji-test.txt` (Unicode) в `node_modules/.cache/pismo-emoji` (в git не хранится) и пишет `src/utils/emojiCatalog.ts`: 9 групп, 1898 эмодзи, каждая группа со значком для вкладки |
| — | из набора выброшены варианты с цветом кожи и группа `Component` («запчасти» конструктора) |

Запуск: `python3 frontend/scripts/build-emoji-catalog.py` (интернет нужен только
для первого скачивания). Файл правками не поддерживается — его затрут при
следующей сборке каталога.

Каталог подключается **динамическим импортом** при открытии панели
(`import('@/utils/emojiCatalog')`): целиком он весит ~5.4 КБ в сжатом виде и в
основном чанке стоил бы этих килобайт каждому запуску. За этим следит
`src/__tests__/emojiCatalogLazy.spec.ts` — как и за ленивым окном паков
стикеров.

**Панель — как в Telegram: лента значков плюс содержимое столбиком.** Сверху
полоса значков (категории эмодзи у панели эмодзи, паки стикеров у панели
стикеров), ниже — вертикальный список секций (`PanelSection.vue`): «Недавние»,
наборы, категории. Лента служит быстрым переходом (тап прокручивает контейнер к
секции) и подсвечивает ту, что сейчас на экране; содержимое секции монтируется
лениво, когда до неё дошли. Так видно сразу всё содержимое (вкладки прятали
категории: «куда уехали остальные?»), а лента не даёт листать вслепую. Лента
листается общим механизмом `composables/useHScroll.ts` (колесо, перетаскивание,
затухание у краёв).

**Стандартные стикеры** — наши собственные картинки, которые есть у всех сразу:
`frontend/scripts/build-standard-stickers.py` рисует плашки-реакции
(«Ок», «Спасибо», «Привет»), кладёт PNG в `public/stickers/<пак>/` и пишет
каталог `src/utils/standardStickers.ts`. Чужие наборы (Telegram и любые другие)
не подходят: это чужие картинки, а их форматы (`.tgs`, `.webm`) мы не
проигрываем. Стандартные паки не удаляются — это часть приложения, поэтому в
окне «Мои стикеры» их не видно; отправка ничем не отличается от своих: клиент
скачивает байты и уходит сообщением с `sticker=true`.

**Свои стикеры** — библиотека на сервере (`/stickers/`), клиент держит её в
`stores/stickers.ts`:

- панель композера: «Недавние» (по id, поэтому удалённый стикер исчезает сам),
  паки человека (картинки), затем эмодзи-стикеры по категориям (тап = крупное
  эмодзи сообщением);
- `StickerPacksDialog.vue` (ленивый чанк): паки, переименование, порядок,
  удаление с подтверждением в строке, загрузка нескольких файлов и сетка с
  удалением по одному;
- отправка: байты стикера скачиваются с сервера и уходят обычным вложением с
  `sticker=true` (`sendAttachmentMessage(..., sticker)`); в E2EE-чате — сначала
  шифрование. Сообщение получает `kind='sticker'`;
- рендер: `MessageRow` рисует такое сообщение без пузыря (`isStickerMessage`), а
  `MessageAttachment` с пропом `sticker` ограничивает картинку 160 px;
- «В стикеры» в меню картинки (`canBecomeSticker`) — только для открытых
  картинок: в E2EE сервер файл не прочитает, и обещать действие нельзя.

**«Добавить весь набор»** — как «ДОБАВИТЬ СТИКЕРЫ» в Телеграме: человек получает
встроенный набор своим паком и может его переименовать, переставить и удалить.
Встроенные картинки лежат статикой в приложении, у сервера их нет, поэтому
добавление — это скачать картинки и загрузить их обычным путём
(`services/stickers.ts::fetchStandardStickerFile` → `uploadSticker`). Логика одна
на два места — окно «Мои стикеры» (блок «Наборы приложения») и панель стикеров
(широкая кнопка под сеткой набора: в ней же виден и ход добавления — счётчик,
ожидание лимита, «Добавлен»), — и живёт в `composables/useStandardSetImport.ts`,
а сам импорт — в `stores/stickers.ts::importStandardSet`.

В панели путь к действию ОДИН — эта кнопка. Меню «⋯» в заголовке секции и
удержание стикера убраны: три входа в одно и то же действие заставляли гадать,
какой из них «настоящий», а прогресс приходилось показывать в двух местах
(состояние считает `setAddStateOf` в `MessageComposer.vue`).

Отметка «набор добавлен» — в `pismo_sticker_imports` (ключ набора → id пака), а не
по названию: пак можно переименовать, и совпадение имён ничего не значит. Удалили
пак — набор снова можно добавить. В «Недавние» импорт не пишет: иначе набор целиком
залил бы их.

Ограничение сервера: `message_upload_limit_per_minute` (10 загрузок в минуту,
429 с `Retry-After`). Набор из 16 стикеров в одно окно не влезает, поэтому
`uploadStickerPacing` ждёт столько, сколько просит сервер, и продолжает — иначе
человек получал бы половину набора. Ожидание видно в подписи кнопки
(«Ждём лимит загрузок (60 с)»). Следит `__tests__/standardSetImport.spec.ts`.

**Публичные (предустановленные) наборы на сервере.** Свой набор публикует
владелец — значок-рупор у пака в окне «Мои стикеры» (`PUT
/stickers/packs/{id}/preset/`). Такой набор виден ВСЕМ секцией в панели, и
добавляется он одним запросом `POST /stickers/presets/{id}/copy/`: сервер копирует
ссылки на файлы, поэтому ни лимит загрузок, ни место в квоте тут не при чём.
Отметки в `pismo_sticker_imports` у серверного набора нет — он «уже добавлен»,
если пак с таким названием есть у человека (`isSetAdded`).

**Передачи пака по ссылке нет** (сознательно). Ссылка на сервере была сделана и
работала, но от неё отказались: набор передаётся одним из двух способов — своя
картинка уходит сообщением и получатель жмёт «В стикеры», а целый набор виден в
панели сразу, если он стандартный. Ссылка добавляла сущность (`share_token`,
`imported_from_pack_id`) и второй способ получить стикеры ради сценария, который
покрывают эти два. Ссылку из Telegram импортировать всё равно нельзя (чужие
картинки + форматы `.tgs`/`.webm`), поэтому поле «добавить по ссылке» только
путало.

### Иконки (Lucide) и шрифты

Иконки в разметке задаются **логическим именем** через `icon()`: `<q-icon :name="icon('close')" />`. Какое имя какому глифу соответствует — решает `src/utils/icons.ts` (`ICON_MAP`), а `icon()` превращает имя в классы иконки (`icon-lucide icon-x`) — набор **Lucide** (тонкий штрих 2px, скруглённые концы; самый ходовой современный стиль).

Почему так:
- Quasar по префиксу `icon-` понимает, что получил **список классов**, а не имя лигатуры. Любое другое значение он рисует ТЕКСТОМ внутри `<i class="material-icons">` — это и была ошибка «иконка как текст».
- Смена набора иконок — правка одного файла `ICON_MAP` (+ пересборка CSS), а не 250 мест в шаблонах.
- Незнакомое имя `icon()` возвращает как есть: его отрисует резервный шрифт Material (Quasar подключён), то есть ошибка видна, а не превращается в пустоту.

Сборка (нужны `fonttools` + `brotli`: `python3 -m venv /tmp/fonts-venv && /tmp/fonts-venv/bin/pip install fonttools brotli`):

| Скрипт | Что делает |
| --- | --- |
| `scripts/fetch_icons.py` | скачивает сборку Lucide (шрифт + карта имён) в `node_modules/.cache/pismo-icons` — в git не хранится |
| `scripts/build_icons.py` | читает `ICON_MAP`, сверяет имена с набором Lucide, режет шрифт до нужных глифов (~16 КБ вместо 281 КБ) и пишет `src/assets/icons.css` |
| `scripts/build-icons-font.py` | резервный шрифт Material Symbols Rounded (урезанный до имён из `src`) — им рисуются внутренние элементы Quasar и имена, которых нет в `ICON_MAP` |
| `scripts/migrate-icons-names.py` | одноразовая миграция: `name="close"` → `:name="icon('close')"` |

**Добавили иконку — допишите её в `ICON_MAP` и прогоните `build_icons.py`** (при первом запуске — ещё `fetch_icons.py`), иначе она отрендерится пустотой. Страж в тестах (`src/__tests__/icons.spec.ts`) проверяет, что все имена из шаблонов есть в мэппинге и что для каждой иконки есть правило в CSS.

Исключение — глифы, которых в наборе нет: они нарисованы вручную в `src/assets/icons-drawn.css` (SVG в data-URI, показывается через `mask`, краска — `currentColor`), имена перечислены в `DRAWN_GLYPHS` (`src/utils/icons.ts`). Сборка шрифта такие имена пропускает, а `icon()` отдаёт им классы `icon-drawn icon-<глиф>` вместо `icon-lucide …`. Файл **не генерируется** — правки в нём пересборка не затирает. Сейчас так нарисован один глиф: `round-video` — видеосообщение («кружок» в квадрате со скруглёнными углами, как в Telegram).

Шрифты (локально, без внешних запросов; собирает `scripts/fetch_fonts.py`) — три роли:

- `--ms-font` → **Roboto** — обычный текст;
- `--ms-font-display` → **Golos Text** — заголовки, названия чатов, шапки диалогов;
- `--ms-font-mono` → **Roboto Mono** — цифры (код из SMS, телефон, таймеры), `tabular-nums`.

Наборы — кириллица + латиница с `unicode-range`, поэтому браузер грузит только нужное (русская страница — ~65 КБ на все три вместо внешней загрузки с Google Fonts).

**Если имени нет в резервном шрифте, Vue отрендерит текст буквами** — тихо и заметно. Проверка (в браузере, консоль на любой странице приложения):

```js
for (const n of ['forum', 'auto_stories', 'group']) {
  const s = document.createElement('span')
  s.style.fontSize = '24px'
  s.textContent = n
  document.body.appendChild(s)
  console.log(n, s.getBoundingClientRect().width) // иконка ≈ 24px, текст сильно шире
  s.remove()
}
```

Список имён из `@quasar/extras/material-symbols-rounded/icons.json` для такой проверки **не годится**: в шрифте есть легаси-лигатуры (`push_pin`, `delete_outline`, `done`, `help_outline`…), которых в JSON нет, — поэтому резервный шрифт собирается по именам, найденным прямо в `src`. Галочки прочтения — текстовые `✓✓`. Не используйте классы PrimeIcons `pi pi-*` (шрифт не подключён).
