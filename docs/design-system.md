# Дизайн-система: геометрия и когда чем открывать

Короткий справочник: какие ступени размеров есть у интерфейса и в каком виде
показывать «ещё один экран». Всё, что здесь описано, закреплено токенами
(`src/assets/appearance.css`) и проверками — не «по договорённости».

## Геометрия: одна шкала на всё приложение

Радиусы задавались литералами в 67 файлах (5, 6, 7, 9, 11, 14, 16, 18, 22,
28px) — соседние окна отличались на 1–2 px и выглядели «не из одного набора».
Теперь ступеней шесть, и ступень выбирается **по смыслу элемента**:

| Токен | Значение | Где уместно |
| --- | --- | --- |
| `--ms-radius-xs` | 6px | чекбокс, тег, мелкая плашка, скелетон |
| `--ms-radius-sm` | 10px | поле ввода, чип, пункт меню, кнопка внутри панели |
| `--ms-radius-md` | 12px | строка списка, мелкая карточка, кнопка |
| `--ms-radius-lg` | 16px | карточка, панель, вложение, всплывающее меню (поповер) |
| `--ms-radius-xl` | 20px | модальное окно и лист снизу |
| `--ms-radius-pill` | 999px | «таблетка»: бейдж, счётчик, круглая кнопка |

Отступы — `--ms-space-1…5` (4/8/12/16/24), внутренний отступ модальной карточки —
`--ms-dialog-pad` (20px), ширина окна — `--ms-dialog-w` / `-sm` / `-lg`
(440 / 380 / 560). Общие размеры текста — `--ms-fs-*`, тени — `--ms-shadow-*`.

**Движение.** Длительности `--ms-dur-fast/-/--ms-dur-slow` (0.15/0.22/0.28 с) и
кривая `--ms-ease` (`cubic-bezier(0.22, 1, 0.36, 1)`). Кривая та же, что у
раскрытия поиска и историй, поэтому панели и окна «дышат» одинаково; свои
`cubic-bezier` в компонентах не заводим. `prefers-reduced-motion` гасит анимации
централизованно (`assets/a11y.css`).

Проверка: `node scripts/check-geometry.mjs` — новые литеральные радиусы и тени в
`<style>` компонентов не проходят (старые записаны в
`scripts/style-geometry-baseline.json` и вычищаются по одному).

**Где страж НЕ смотрит** (и почему): общие слои `assets/*.css` — `appearance.css`,
`quasar.css`, `rows.css`, `overlays.css`. Это и есть место, где геометрия задаётся
(базовые кнопки, строки списка, окна), поэтому литералы там — норма. Смысл стража в
другом: `<style>` конкретного компонента не должен заводить свою ступень.

## Чем открывать: модальное окно, лист, панель или полный экран

Четыре формы, и выбор между ними — по **задаче**, а не по привычке. Раньше один
и тот же по смыслу экран открывался то центрированным окном, то полноэкранной
модалкой, потому что решения принимались в каждом компоненте отдельно.

| Задача | Форма | Механизм |
| --- | --- | --- |
| Форма, выбор из списка, подтверждение («создать канал», «звук уведомлений», «удалить сообщение») | **Окно** — на планшете/десктопе карточка по центру, на телефоне лист снизу во всю ширину со скруглением сверху | `q-dialog` + `<q-card>`; геометрия берётся из общего правила `.q-dialog__inner > .q-card` (`assets/quasar.css`) |
| То же, но нужна своя разметка или позиционирование (пересылка, «поделиться», внешняя ссылка, импорт контактов) | **Окно** с тем же видом | `Teleport to="body"` + классы `.ms-overlay` / `.ms-overlay-card` (`assets/overlays.css`) + `useFocusTrap` |
| Навигация по разделам внутри экрана (настройки, инфо о канале) | **Полный экран** на телефоне, окно на десктопе | `q-dialog` с `:maximized="!isDesktop"` + класс-модификатор `.ms-modal-full` |
| Контекстные действия по объекту (долгое нажатие по сообщению или чату) | **Лист действий** — всегда от низа экрана | `MessageActionSheet.vue` |
| Справочная информация о чате на широком экране | **Правая колонка** 340px, а не окно | `.chat-rail` + режим `panel` у `ChatInfo` / `GroupChatInfo` (≥ 1280px) |
| Просмотр медиа и звонок (лайтбокс, истории, кружок-видео, запись видео, звонок) | **Полноэкранный тёмный слой** на любой ширине | свой слой (`CallOverlay`, `ImageLightbox`, `StoryViewer`), вне шкалы окон |

Инварианты у любой из форм (иначе «окна ведут себя по-разному»):

- подложка — одна: `--ms-backdrop` (в тёмной и AMOLED теме темнее, см.
  `quasar.css`), слой — `--ms-z-overlay`; выше только полноэкранные медиа-слои;
- фокус удерживается внутри слоя (`useFocusTrap` или `q-dialog`), после закрытия
  возвращается туда, откуда окно открыли;
- закрытие — клик по подложке, `Esc`, кнопка «закрыть»; у окна с вводом —
  `mousedown.self`, чтобы случайный клик по подложке не терял набранное (см.
  `ExternalLinkDialog` — там подложка закрывает только осознанно);
- прокрутка одна и внутри тела окна: шапка и кнопки стоят на месте, `max-height`
  — `min(640px, 100vh - 32px)`, на телефоне `92dvh`; низ учитывает
  `env(safe-area-inset-bottom)`;
- появление — `ms-overlay-fade` + `ms-overlay-pop` (или встроенная анимация
  `q-dialog`), без своих `@keyframes` в компоненте.

### Что делать, когда добавляешь новый экран

1. Реши по таблице, окно это, лист или панель.
2. Если окно — бери `q-dialog` с `<q-card>` и **не задавай** `border-radius`,
   фон, тень и `width` вручную: это уже общее правило. Отличается только
   ширина — тогда `--ms-dialog-w-sm` / `--ms-dialog-w-lg` в `width`.
3. Если своя разметка — навешивай `.ms-overlay` + `.ms-overlay-card` и не
   повторяй `position: fixed; inset: 0; z-index; background; display: flex`:
   это уже в общем слое.
4. Заголовок — `.ms-overlay-title` (или `q-card-section` + `q-separator`, как в
   диалогах Quasar), текст — `--ms-fs-*`, отступы — `--ms-space-*`.
5. Прогони `make check-frontend` — страж геометрии поймает новые литералы.
