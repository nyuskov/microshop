# РКН: что конкретно сделать — чеклист

Короткий список действий. Подробные формулировки для полей формы —
`docs/rkn-notification.md` (§3), оттуда можно копировать текст.

## Этап 1. Собрать данные (10 минут)

- [ ] Адрес места жительства (как в паспорте)
- [ ] ИНН физлица (если есть)
- [ ] Контактный телефон для формы
- [ ] Дата начала обработки — когда появились реальные пользователи
- [ ] Адрес дата-центра (Москва, Cloud.ru — точный адрес из договора с хостингом)

## Этап 2. Подготовить вход

- [ ] Проверить, что учётная запись Госуслуг **подтверждённая** (уровень «подтверждённая»)
- [ ] Зайти на `https://pd.rkn.gov.ru/` и проверить вход через ЕСИА

## Этап 3. Подать основное уведомление

- [ ] Портал → **«Подать уведомление»** → тип **«Уведомление об обработке персональных данных»**
- [ ] Категория оператора — **физическое лицо**; заполнить ФИО, адрес, ИНН, телефон, e-mail
- [ ] Цели обработки — списком из `docs/rkn-notification.md` §3 (готовая версия):
      регистрация и аутентификация, обмен сообщениями и медиа, звонки, уведомления,
      безопасность аккаунтов и журнал событий, поддержка, исполнение закона +
      фраза о соответствии фактической деятельности и ст. 6 152-ФЗ (учредительных
      документов у физлица нет)
- [ ] Правовые основания — согласие (ст. 6 ч. 1 п. 1) + договор (ст. 6 ч. 1 п. 5), сослаться на `https://pismo.space/terms.html`
- [ ] Категории ПДн — «иные категории», состав из §3
- [ ] Категории субъектов — пользователи, посетители сайта, обратившиеся по ПДн
- [ ] Перечень действий — стандартный список (сбор → уничтожение), способ обработки **смешанная**
- [ ] Место хранения БД — **Российская Федерация, г. Москва**; лицо, которому поручена обработка — хостинг-провайдер (ООО «Клауд Технологии»)
- [ ] Трансграничная передача — ответить **«осуществляется»** (web push через Google/Apple/Mozilla)
- [ ] Меры по ст. 18.1 и 19 — текст из §3 инструкции (организационные и правовые меры)
- [ ] **Средства обеспечения безопасности** — отдельное поле, текст из §3 (технические меры)
- [ ] Ответственный за организацию обработки ПДн — вы (ФИО + e-mail)
- [ ] Сохранить у себя внутренние документы (решение о назначении ответственного,
      перечень ПДн и мест хранения, оценка вреда) — шаблоны в
      `docs/pd-internal-documents.md`
- [ ] Проверить → **подписать через ЕСИА** → отправить
- [ ] Сохранить черновик и дождаться письма (до 30 дней; чаще 1–2 недели)
- [ ] При уточнении от РКН — исправить **тот же черновик** и отправить повторно

## Этап 4. Второе уведомление — трансграничная передача

- [ ] Портал → тип **«Уведомление о трансграничной передаче персональных данных»**
- [ ] Данные: push-подписка (endpoint + ключи), имя отправителя, текст уведомления до 120 символов
- [ ] Получатели: Google LLC (США), Apple, Mozilla; цель — доставка уведомлений
- [ ] Основание: согласие (push включается вручную) + исполнение договора
- [ ] Формулировки — §6.3 инструкции

## Этап 5. Убрать почтовый поток за границу (это про код, делаю я)

- [ ] Завести ящик на домене `pismo.space` в Яндекс 360
- [ ] Включить двухфакторную аутентификацию, создать **пароль приложения**
- [ ] Добавить DNS: MX Яндекса, SPF (`v=spf1 redirect=_spf.yandex.net`), DKIM, DMARC
- [ ] Вписать в `.env` на проде (пароль вводите сами, я секреты не запрашиваю):
      `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`, `SMTP_SSL=true`,
      `SMTP_STARTTLS=false`, `SMTP_USER=no-reply@pismo.space`,
      `SMTP_FROM=no-reply@pismo.space`
- [ ] Сказать мне «готово» — проверю отправку письма с кодом и `email_otp_available`

## Этап 6. После регистрации

- [ ] Сохранить номер записи в реестре операторов и дату
- [ ] Добавить в политику строку «Оператор внесён в реестр операторов (запись №___ от ___)» — сделаю я
- [ ] Завести напоминание раз в год: сведения в реестре должны совпадать с реальностью
- [ ] Любое существенное изменение (новые цели, смена места хранения, статус ИП) — уведомление о внесении изменений
