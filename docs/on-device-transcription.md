# Расшифровка голосовых на устройстве

Кнопка «в текст» у голосового сообщения расшифровывает запись **на самом
устройстве**: модель Whisper (WebAssembly) исполняется в браузере, звук и текст
никуда не отправляются. Сервер в распознавании не участвует вовсе — иначе
ломается обещание E2EE (§6 политики конфиденциальности), а серверное
распознавание требует отправки аудио на нашу сторону.

## Кто распознаёт запись (три пути)

| Путь | Где работает | Чем распознаёт | Код |
| --- | --- | --- | --- |
| Нативный распознаватель | приложение (Android-обёртка) | системный сервис устройства (`EXTRA_AUDIO_SOURCE`) | `frontend/src/services/nativeSpeech.ts` |
| `SpeechRecognition.start(MediaStreamTrack)` | Chrome **на компьютере** | сервис браузера, звук ЗАПИСИ | `frontend/src/utils/voiceRecognition.ts` |
| Модель на устройстве | все остальные (в том числе PWA на телефоне) | Whisper в браузере | `frontend/src/utils/localSpeech.ts` |

Мобильный Chrome и Safari слушают микрофон, а переданную дорожку молча
игнорируют — поэтому «в текст» там идёт через модель. Разбор ошибок и
ограничений — в [gotchas.md](gotchas.md), раздел про распознавание речи.

Модель скачивается в браузер один раз (кэш `transformers-cache`), дальше работает
офлайн: повторное распознавание сети не требует. Скачивание идёт только с согласия
человека — перед первым разом показывается вопрос с размером загрузки.

## Что лежит на нашем сервере (`/stt/`)

Публичные CDN для этой функции не годятся: из мобильных сетей РФ недоступны ни
`cdn.jsdelivr.net` (движок), ни `huggingface.co` (модели), а `connect-src 'self'` в
CSP прода запрещает чужие источники. Поэтому движок, его рантайм и модели отдаёт
наш nginx:

| Файл | Размер | Что это |
| --- | --- | --- |
| `manifest.json` | 40 Б | что лежит рядом: `{"engine":"…","models":true}` |
| `transformers-bundled.js` | 820 КБ | движок transformers.js 3.6.0, собранный одним модулем |
| `ort-wasm-simd-threaded.jsep.mjs` | 43 КБ | загрузчик рантайма ONNX |
| `ort-wasm-simd-threaded.jsep.wasm` | 21,6 МБ | сам рантайм ONNX (в нём считаются модели) |
| `models/Xenova/whisper-tiny/resolve/main/…` | 42 МБ | быстрая модель |
| `models/Xenova/whisper-base/resolve/main/…` | 76 МБ | точная модель |

Раскладка моделей повторяет структуру репозитория на Hugging Face, потому что
движок собирает адрес как `{remoteHost}/models/{repo}/resolve/main/{file}`
(`env.remoteHost` + `env.remotePathTemplate` в `localSpeech.ts`).

Как это устроено на хосте:

- каталог `~/pismo-stt` на сервере (bind mount через `PISMO_STT_DIR` в
  `docker-compose.prod.yaml`) → внутри контейнера `/usr/share/nginx/html/stt`;
- отдельный `location /stt/` в `frontend/nginx-prod/default.conf` с
  `try_files $uri =404`;
- **не** том `frontend_html`: ассеты весят 140 МБ, обновляются редко и не
  собираются вместе с интерфейсом — в томе их пришлось бы копировать каждый деплой.

## Как выложить или обновить

```sh
scripts/stt/publish.sh          # собрать движок → залить на сервер → модели туда же
```

Что делают шаги:

- `scripts/stt/build-engine.sh` — ставит `@huggingface/transformers` во временный
  каталог и собирает его `esbuild` в один самодостаточный модуль (у пакета из npm
  есть внешние зависимости, в браузере их взять неоткуда). Версия движка —
  переменная `TRANSFORMERS_VERSION`, по умолчанию закреплена в скрипте и должна
  совпадать с `ENGINE_VERSION` в `localSpeech.ts`.
- `scripts/stt/fetch-models.sh` — качает файлы моделей **на сервере** (он видит
  huggingface.co, машина разработчика тут не нужна).
- `scripts/stt/publish.sh` — `scp` движка и рантайма, запуск предыдущего скрипта по
  ssh, запись `manifest.json`.

После выкладки ничего перезапускать не нужно: файлы читаются из bind mount, а
nginx отдаёт их сразу. Пересоздание контейнера фронтенда нужно только один раз —
когда в compose появляется сам mount (это делает обычный деплой).

## Как проверить

```sh
curl -sI https://pismo.space/stt/transformers-bundled.js            # ждём 200 и text/javascript
curl -sI https://pismo.space/stt/ort-wasm-simd-threaded.jsep.wasm   # ждём application/wasm
curl -s  https://pismo.space/stt/manifest.json                      # ждём {"engine":…,"models":true}
curl -s  https://pismo.space/stt/models/Xenova/whisper-tiny/resolve/main/config.json
curl -sI https://pismo.space/stt/нет-такого.js                      # ждём 404, а не 200 с HTML
```

Главная ловушка — **SPA-фолбэк**: без отдельного `location` nginx отвечает на
неизвестный путь кодом 200 и страницей `index.html`, движок «успешно»
импортирует разметку и падает на разборе (человек видит «Не удалось загрузить
движок распознавания»). Поэтому у `/stt/` свой `location` с `=404`, а проба своих
ассетов (`ownAssetsManifest`) разбирает JSON и требует в нём поле `engine`.

Живая проверка — на телефоне: открыть голосовое сообщение и нажать «в текст». В
консоли браузера видно, что запросы идут на `/stt/…`, а не на jsdelivr и
huggingface. Юнит-тесты контракта — `frontend/src/__tests__/localSpeech.spec.ts`.

## CSP: два разрешения, без которых ничего не запустится

В продакшене CSP ставит nginx (`frontend/nginx-prod/default.conf`):

- `script-src 'self' 'wasm-unsafe-eval'` — без этого разрешения браузер запрещает
  компилировать WebAssembly, и модель падает на инициализации ONNX;
- `worker-src 'self' blob:` — onnxruntime-web поднимает свой рабочий поток из
  blob-ссылки.

`connect-src` остаётся `'self' wss: https://api.giphy.com`: чужие CDN для
распознавания не нужны, потому что файлы отдаём мы (см. выше). В разработке CSP нет,
поэтому там всё работает и с чужих адресов.

## Модели и числа

| Модель | Размер загрузки | Компьютер, 18 с русской речи |
| --- | --- | --- |
| `tiny` | 42 МБ | 2,1 с |
| `base` | 76 МБ | 3,1 с (разборчивее на числах и окончаниях) |

Модель выбирается по устройству (`defaultLocalSpeechModel`): на слабом (≤4 ядра или
≤4 ГБ памяти) — `tiny`, иначе `base`. Выбор помнится в `localStorage.pismo_stt_model`,
`forgetLocalSpeech()` чистит и кэш моделей, и выбор. Замеров на телефоне пока нет —
первое распознавание там дольше: скачивание рантайма и модели плюс сама расшифровка.

Чего ещё нет: ручного выбора модели в разделе «Устройство» (сейчас только по
устройству), кнопки «удалить модель» и замеров на телефоне.

## Разработка

Своих ассетов в репозитории нет (`/stt/` живёт только на сервере): 140 МБ моделей и
21 МБ рантайма в git не место. Если положить их в `frontend/public/stt/`, Vite их не
отдаст — импорт из `public/` он отклоняет («This file is in /public and will be
copied as-is during build … should not be imported from source code»). Поэтому в
разработке движок берётся с jsdelivr, а модели с Hugging Face; на проде — со своего
сервера. Проба окружения разработки описана в [gotchas.md](gotchas.md): медиа в
dev-базе зашифровано, для проверки нужен синтез речи (gTTS → WAV 16 кГц моно).
